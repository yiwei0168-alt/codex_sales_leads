# G09 运行包的依赖字节核对

## 实现

运行包检查器在既有入口完整清单校验后，对已验证清单中的全部 `node_modules/` 文件与链接生成 `dependencyManifestHash` 和 `dependencyFiles`。绑定实际文件摘要及链接目标，不以包版本号代替内容；拒绝异常路径、缺失/混合描述、逃离依赖根目录的链接及空清单。测量函数在镜像内执行，使用同一摘要协议；不读取业务资料或密钥。

登记文档沿用 v1，两个新增字段成对可选。旧不可变文档可以继续读取，但缺依赖测量时不获得字节成对通过结果，不自动改写或补填历史。新的运维发布从实际镜像检查结果派生字段，不接受调用者自报依赖摘要。

持锁登记读取在完成原有最新版本、摘要、公钥、用途、来源和时间核对后，对三用途 `task-model-transport`、`model-transport`、`runner-declaration` 比较源码提交/指纹/输入数、Node版本/二进制、平台/架构和依赖清单。缺用途、缺测量或任何字节身份不一致，返回独立的 `runtimePackageBytesPairBlockers`。单份登记有效与成对字节一致分别报告；readiness沿用现有返回结构带出该结果，生产来源及自动启用保持false。

## 实测

- 107项定向单元回归、全项目类型及九文件lint通过。含三用途持锁读取编排、相同版本但不同依赖字节拒绝、缺用途/旧文档不提升、源/Node/架构不符、链接逃逸和纯函数镜像内序列化。
- 初选旧7d1f382c采集器被原入口拒绝。独立只读诊断发现其34487个清单项目中，`runner.cjs`与内置摘要不符，Node及运行边界通过。原因不据此归结为磁盘迁移；旧失败保留，没有跳过入口。
- 重新从干净Git627f1990构建主运行和采集器，两者均退出0。新不可变镜像实际入口完整性、部署绑定和依赖测量通过：源码输入977项，Node24.21.0及二进制一致；33503个依赖文件/链接，依赖摘要一致。两种角色的执行产物和完整清单数量允许不同。
- 本机检查CLI仅接受两个不可变镜像ID，离线、只读、非root、无capabilities且禁止提权；临时容器自动清理。没有登记、业务库操作或模型调用。
