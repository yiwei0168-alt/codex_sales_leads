# MA17 synchronous GLM 5.3 route — 2026-09-22

The user confirmed synchronous GLM 5.3 for new main-Agent conversations after observing a WR3000 question wait over 13 minutes for the first Batch result. That first result requested two `describe_tool` calls; it had not searched product evidence. The model-selection change addresses the Batch wait, while reducing description turns remains a separate design decision.

Implementation: `defaultModelConfig()` now returns `z-ai/glm-5.3` / `fireworks`; `.env.example` and the local untracked `.env.local` use the same route. Existing runs carry `model_config` in `agent_run`, so they continue with their saved route. The synchronous transport retains explicit provider pinning, disabled provider data collection, durable call journaling and the existing financial-admission policy. The Batch transport and poller remain available for historical tasks.

Validation: the public OpenRouter GLM 5.3 endpoint listing showed Fireworks support for `tools`, `tool_choice` and `max_tokens`, but did not list `parallel_tool_calls` or `max_completion_tokens`; the synchronous GLM request uses only the advertised fields with `require_parameters=true`. A mocked-transport contract test confirms one `/api/v1/chat/completions` request with the expected model, provider, tools and parameter shape. The full suite passed 1,319 tests (one existing skip), the targeted protocol tests passed after the parameter correction, TypeScript passed, and lint had zero errors (11 existing warnings). The final production build and nine static assets passed; the sole Next service returned HTTP 200, the restarted LangGraph health/schema probe made zero external provider calls, and one worker was running. The service switch occurred when the local database had no running/queued Agent tasks or pending Batch receipts. No provider inference was made for the protocol test. Real answer quality, latency and provider charges are not implied by local protocol checks. The local `PRODUCT_FINANCIAL_POLICY=observe` setting is separate from the route switch; deployments without an admitted GLM synchronous tariff or that policy can still reject a paid request.
