# G09 前瞻候选正式任务与持续审核

对应既有 MA24-06，无新增用户确认。前瞻登记和原流程仍由原任务负责，候选在原流程完成后使用独立隐藏任务执行。候选复用原流程的精确只读回执，不产生新的业务工具效果；本阶段不授予生产执行等价或质量资格。

## 来源与执行

- 候选任务规范同时绑定前瞻捕获记录 ID、完整来源投影摘要、原任务、冻结、评测及 Skill。历史候选不增加前瞻字段，保持既有绑定内容。
- 准入、工具上下文复核、结果结算和完成任务读取都重建前瞻来源。现有登记时间不晚于冻结、冻结不晚于捕获、捕获不晚于原任务开始的要求保留；还核对捕获所属原任务以及基线没有使用待评测 Skill。
- 配置入口的历史与前瞻候选共用显式认领、正式只读日志、模型签名快照和检查点。失败不回退旧候选执行器。
- 已完成前瞻任务通过重新审计完成元数据和模型/工具日志复用，不重复请求或调用工具。

## 收集、审核和持锁来源

带 `taskId` 的前瞻引用使用新协议审计，生成 `prospective-collector-v2`；旧引用保留原只读重建。统一审核按两臂标记实际消费回执，核对新日志摘要，并在返回前再次重建来源。新任务与工具日志纳入既有材料持锁和持续来源指纹；前瞻捕获 ID 必须与任务规范一致，跨类型重复任务引用拒绝。

## 验证进展

70 项定向测试、全项目类型检查和十二文件 Lint 通过。初次新增审核测试将查询参数位置写错，导致正例被原校验拒绝；修正测试替身参数后通过，未放宽产品校验。

首轮新建迁移至 169 的实际前瞻编译入口数据库案例退出 0：前瞻任务规范、捕获身份与模型快照绑定、禁止请求条件下的完成任务复用、模型/工具/唯一材料不变及统一审核两臂证据通过。临时资源已清理，实际模型调用 0，Skill 保持禁用。

随后材料持锁校验增加捕获投影摘要的精确匹配；相关 15 项测试、类型和四文件 Lint 复验通过。第二轮新建 169 数据库补验退出 0：实际材料任务/工具行锁取得与来源指纹返回，错误捕获投影摘要、缺少捕获 ID、其他捕获记录 ID 拒绝，以及正确绑定回读均通过。首轮收据不覆盖该后续改动；第二轮覆盖当前代码。[收据](evidence/ma24-g09-prospective-runtime-entry-2026-10-21.json)。

本阶段没有注入前瞻任务/工具锁竞争，也没有重新构建固定 Linux 镜像或执行完整五类组合。网络/费用适配器和任务内容为合成夹具，本地登记密钥不构成真实提供方身份或人工质量证据。
