# 保存成功后中断的重试身份

阶段75修复 A06/A12 的实际恢复缺陷。`persist_results` 在每次执行时重新生成本节点起止时间；若事务已提交、后续 completed 状态写入失败，检查点仍停在保存节点。旧指纹包含时间，重复保存因而可能误报业务冲突。

新写入采用 `result-input-v2`：仅在指纹计算中去除 `persist_results` 的 `startedAt`、`completedAt`，其余业务输入、费用、阶段数据和观测保持严格比较。数据库保留首次保存的时间及事件；幂等重试不更新公司版本、不再次分摊、不重复记录采用。通用 JSON 指纹和原计划身份核验未变。

无版本的历史指纹继续按全部原输入比较，未知版本拒绝；不迁移历史行、不放宽旧数据的冲突检测。因此本修复不等于旧终结缺项任务已恢复，也不能修复缺失原保存输入的历史任务。回滚应先保留含 v2 元数据的任务，不能把这些行交由旧版本自动重放；无 schema 变更。

验证：

- `npm.cmd test`：840 tests / 184 files 全通过。新增图测试在保存返回后注入 completed 状态故障，重建图后仅重试保存，发现/校正/评分各执行一次，原额度保留。
- `scripts/verify-result-persistence.ts`：真实产品 SQL，两国4并发、2次时间变化重试，仍为1个公共身份、2个国家版本各 revision1、14个原事件、2个证据快照。6次业务输入冲突拒绝，2次旧版本精确复用、2次旧版本时间冲突拒绝、2次无指纹拒绝通过。
- 原合成预留总计23微美元保留且分摊守恒。无业务供应商调用、真实费用或发信，fixture清理。
- 生产构建含类型检查、改动文件 lint 通过；工作流生成文档已更新。Chrome52组证据沿用阶段73，不声称本轮重新浏览器验收。

效率边界：重试不重新消费模型/API，也不将技术中断记为业务不合格；SQL失败尝试尚未形成完整的追加式阶段延迟/重试遥测，保持未观测，不能把首次记录解释为全部重试成本。完整旧任务恢复和最小真实业务闭环仍待完成。
