# G09 自动启用的来源事务封闭

对应既有规则 MA24-06，未新增用户确认。迁移162与最终启用适配器在完成来源重建后封闭当前数据库事务：只允许一次精确的账户 Skill 启用、一次对应工具回执完成、一次对应启用审计。其他受保护来源的 INSERT/UPDATE/DELETE/TRUNCATE 均拒绝，事务整体回滚。

## 实现与边界

- 私有状态表按数据库事务编号保存随机封闭编号、账号/任务/调用/版本/包/证明摘要、期限及三次写入标记，不保存正文或租约密钥。应用与采集器均无直接读写权限。
- 允许的三种语句仍逐行检查身份、字段、顺序及单次标记；其余语句在原有来源准入触发器之前拒绝，包括不命中记录的 UPDATE。逐语句、逐行及 TRUNCATE 守卫的准确函数、事件、启用状态，以及延迟提交守卫均需通过健康检查，否则不能封闭。
- 提交守卫挂在私有状态 INSERT 上，因此只封闭而漏写 Skill、回执或审计也不能提交。适配器显式将三个提交守卫设为 deferred。
- 私有状态不因提前执行该约束而删除；重置自定义变量或再次调用封闭入口不能解除保护。提交后状态不影响其他事务；入口仅限量清理其他已提交事务中超过一天的临时状态，每次最多1000条，审计和提供方收据不清理。
- 自动绑定增加必填 sourceFenceId；旧自动绑定缺字段时拒绝，无绑定的人工路径保持既有行为。

受保护表清单以迁移中的 `skill_activation_source_tables()` 为准，涉及账号/原任务/消息/调用、Skill/评测/捕获、记忆、知识与原件元数据、邮箱客户，以及信任登记和运行包。数据库触发器不使磁盘文件成为不可变存储，也不替代跨事务的来源锁及绑定重查。

## 验证范围

最终实测结果见[结构化证据](evidence/ma24-g09-source-transaction-fence-2026-10-20.json)。临时数据库顺序迁移至162，并重复安装本迁移以核对可重入性。使用受限应用角色验证合法三元写入、缺失元组拒绝提交、私有状态权限、守卫停用拒绝，以及启用函数返回后对记忆、原任务、原消息、工具回执、知识、邮箱的写入拒绝与整体回滚；另检查重封闭、自定义变量重置、提前执行私有约束后继续写入及零命中更新。

“提前执行约束”用例仅证明来源封闭仍存在，不证明任意 SQL 主动提前执行所有时间约束后长时间空闲的时效保护。正常服务端协议显式延迟约束；受信任的数据库管理员禁用触发器不属于应用写入权限范围。

正向资格仍使用明确标识的 readiness 替身，数据库约束与事务回滚为真实执行。没有真实模型请求、human质量批准、生产资格或自动启用；业务数据库未迁移。固定 Linux 包完整组合与未知提交结果恢复不在本轮范围。

## 剩余

该阶段关闭同一事务晚期数据库来源写入这一具体缺口，G09仍未完成。全部来源联合验收、可信生产 runner/collector及运行等价性生产者、真实质量、当前固定包完整链和最终启用提交丢确认仍待完成。`sourceRevocationsLocked`、`collectorProvenanceVerified`及生产自动启用不因此改为通过。当前只推进G01–G13；G14–G20与上线继续暂缓。
