# 混合执行策略第一版

确认依据：用户先提出在完整性与效率/成本之间采用混合策略，随后明确要求“好的，推进混合策略”。规则 ID：HYBRID-01。确认实施方向不等于工程、线上或真实业务验收通过。

## 执行路径

| 路径 | 已实现入口 | 适用范围 | 转回动态规划 |
| --- | --- | --- | --- |
| 固定只读流程 | `workflow_read` | `customer_recent`：候选公司查找→唯一客户时间线→最近邮件原文；`knowledge_evidence`：知识证据检索 | 公司不唯一、缺资料、需求未覆盖、需要更早邮件或更多字段 |
| 动态规划 | 原有 discover/describe/execute | 语义复杂、模糊或混合需求，以及原有写入、审批、外部研究 | 始终保留，可在任何读取结果后选择其他工具 |
| 程序化读取 | `programmatic_read` | 多对象读取、分页、循环、过滤和组合；可调用同一固定流程模块 | 资源上限、未知收据、失败、缺参数、能力超出允许范围 |

路由不改写原始问题，不把复杂推理等同于 interpreter，也不自动切换用户选择的快速／标准／深度模型模式。固定流程不会把候选公司视为已确认别名，不合并公司。

首次请求若完整匹配“查看／查询／总结 + 明确英文公司名或域名 + 最新／近期／最近进展”，且无历史、附件、知识集合限制、补充指令及当前有效决策记忆，可直接生成一次固定流程调用，跳过初始规划模型。存在决策记忆时先让模型理解政策，再选择固定流程。其他请求只收到可修改的路径建议，由现有模型决定。首轮选错后可继续动态工具；已读结果留在上下文中。

**独立快速模型／SLM 路由尚未接入。** 本版先使用零模型成本的保守规则和现有模型的首轮决策；没有把新增路由模型耗时强加给所有请求。后续在真实样本中比较规则命中率、错误升级和增加的一轮模型成本，再决定是否启用独立路由模型。不训练本地 SLM，不变更既有模型供应商或模式配置。

## 程序与工具边界

实现使用锁定 `quickjs-emscripten@0.32.0` 的独立 WASM 堆，每次调用创建新环境。同步 JavaScript 通过 Asyncify 等待异步宿主工具；不开放宿主对象、模块加载器、网络、文件、shell、凭据、时钟或随机数。

```js
const rows = [];
for (const id of ['已解析的客户候选编号一', '已解析的客户候选编号二']) {
  const response = tools.call('company_read', { candidateId: id });
  rows.push({ id, response });
}
return rows;
```

`tools.workflow({workflow:'customer_recent',query:'明确公司名'})` 可复用固定流程。禁止 `await` 式编排，返回 Promise 会失败。实际工具名称和输入由服务器白名单、原 dispatcher/schema、当前账户、模式和知识集合共同检查；不是“effect=read 就全部放行”。本版不开放收费外部搜索、评分、发送、发布和递归 interpreter。它们仍通过普通动态工具和原审批执行。

工程限额（实施参数，非用户指定业务规则）：代码 16,000 字符；工具输入 JSON 32,000 字符；每次最多 16 个叶读取；原始叶结果累积 1,000,000 字符后停止追加读取；单个已完成叶结果仍保留；程序输出 60,000 字符；QuickJS 堆 16 MiB、栈 512 KiB、计算时间 2 秒、程序墙钟 60 秒。墙钟在计算及工具边界检查，已进入的数据库读取仍遵守原数据库超时，不声称可以强行中止在途 I/O。

客户固定流程默认读最新 3 封原文，可显式选择 1–8 封，时间线首屏最多 20 条，明确披露更早邮件未读及“仅已导入邮件”范围。知识流程读取最多 8 块候选证据，不声称全面阅读了整个知识库。

## 恢复与证据

- 父调用与叶工具均通过既有持久执行器。叶键绑定父收据、实现版本、完整程序／流程参数、顺序和实际叶参数；恢复复用已完成叶收据，未知叶不自动重放。
- 脚本无法吞掉租约、补充指令或来源失效异常后继续成功。每个叶仍经过正常边界；控制变更交回图处理。
- 宿主保存 `leaves` 原始结果；脚本只能生成 `value` 投影，不能改写收据。模型视图压缩原始结果，但来源守卫和最终事务从原始收据检查知识、记忆与邮件。
- 原始叶来源、版本、引用位置不能被程序投影替换；投影本身不是新事实。正文不足、失败、超限和未读范围明确保留。
- 历史独立测评入口不增加混合能力；既有评分政策、搜索策略、邮件同步规则不变。

## 交付与验收状态

源码实现与本地定向测试见 [工程证据](evidence/hybrid-execution-v1-2026-11-05.json)。没有调用付费模型，没有读取真实业务邮件来测试，不据此关闭 G07/G08 自然样本要求。

默认新任务允许混合入口；`ENABLE_HYBRID_EXECUTION=0` 关闭固定首动作和两个组合工具，继续原有动态能力。停止开关不会撤销已完成只读结果。当前运行的归档产品不会因源码变化自动升级，候选构建与运行切换须分别记录。

后续真实验收：同一明确最新进展问题、带日期／额外条件问题、同名公司歧义问题、多客户对照问题；逐项核对需求覆盖、事实／引用、未读披露和动态补证。效率和成本采用用户请求范围内的真实端到端对照，不套用供应商基准百分比，不新增开发费用台账。
