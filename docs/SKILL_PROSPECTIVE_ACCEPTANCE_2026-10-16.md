# Skill 前瞻来源到统一验收（G08/G10，2026-10-16）

当前完成来源绑定组件 `skill-prospective-source.ts`，并通过全新临时数据库的捕获触发器和来源守卫集成；两臂日志重建到统一观察的追加收集代码也已实现。完整两臂数据库日志集成、统一材料 API 及审核页面尚未接通。没有运行真实模型影子任务，也没有生成新的质量判决或自动启用资格。

组件只接受冻结计划中 `shadow / prospective-task` 的账户案例。查询按账号、Skill 与版本读取服务器捕获记录和已完成主任务；用首条 `main_model` 持久调用的时间作为任务模型执行开始，要求顺序为：影子登记 ≤ 计划冻结 ≤ 服务器捕获 ≤ 首次模型调用 ≤ 任务完成 < 计划到期。缺少模型调用或完成时间会拒绝，不能事后把历史结果改称前瞻。

案例的输入哈希绑定原始任务输入，来源哈希绑定任务开始前的服务器 `start_context`；模型配置与计划身份一致，捕获中的 Skill 内容和来源哈希必须与固定版本一致。复用 `prepareSkillShadow` 重核当前来源权限、版本、原任务最终状态和读取收据；首版只接整项只读任务，原有受限子任务保持自己的审核入口，后续须另行实现可比较的子任务合同。

读取前后重新查询捕获与权限快照，并再次验证冻结仍有效。返回内容只包含绑定投影、哈希和时间，不返回原任务正文。已有本地 Qwen 配对结果不作为正式模型原臂或候选臂；后续必须用实际持久模型收据重建两臂答案、引用和工具结果，再生成统一观察并提供审核材料。

16 项定向测试使用模拟的服务器读取，覆盖时间顺序、输入/配置/Skill 变化、跨账号、缺捕获、子任务替换、读取期间变化和冻结撤销。类型与 lint 通过。[组件收据](evidence/ma24-g10-prospective-source-binding-2026-10-16.json)。

随后在全新一次性 PostgreSQL/pgvector 中，先登记影子并用服务器 SQL 哈希生成预期开始快照，冻结计划后才插入任务。真实生命周期触发器保存的开始快照与计划一致；合成模型记录及加密邮件读取收据通过来源重校。任务结束后另建冻结被拒，邮件清除标记和冻结撤销均阻断读取；恢复标记后投影哈希不变。容器已清理，HTTP 被阻断，外部模型/IMAP/发信均为 0。[数据库收据](evidence/ma24-g10-prospective-source-database-2026-10-16.json)。

`skill-prospective-collector.ts` 现在从前瞻来源取得原任务 ID，分别调用原任务图日志重建和固定 Skill 的候选日志重建；两臂的输入、模型配置、路由/收据、冻结和时间必须匹配。候选须在原任务完成后按现有只读回放机制执行，且确实使用固定 Skill。来源捕获的时间用于观察的 `capturedAt`，原任务首次模型调用用于 `taskStartedAt`，候选完成时间用于观察完成时间。收集前后重建三条投影和当前运行身份，禁止调用方提交观察正文。

来源守卫另行拒绝原任务已经固定使用被评测 Skill 的情况，避免把已使用该 Skill 的任务当成未使用对照。追加收集保存两臂投影及来源引用，事务中再次检查冻结和专用采集角色，并核对入库材料哈希；来源类别原样保留，运行真实性与自动启用标记仍为 false。

来源与收集两文件共 34 项测试通过，收集器的日志和数据库写入边界使用模拟；实际临时库来源路径因新增基线检查而复跑通过。[收据](evidence/ma24-g10-prospective-observation-collector-2026-10-16.json)。完整两臂模型日志贯穿收集存储、材料重读和页面/API 到库验收仍待完成；合成模型记录不代表正式模型回答。历史捕获若不满足冻结顺序，按不合格来源处理。
