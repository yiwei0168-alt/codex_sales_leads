## 设计与执行顺序

当前四选一提示混合了任务类型、执行能力和公司是否已识别。候选改为同一次请求的三个独立 Choice：需要开放规划、适合固定查询、适合本地批量处理。公司/产品已具名但未读数据库不再等同于缺少指代；不虚构唯一匹配结果。公司实际匹配、权限、参数和资料可用性仍须执行阶段验证。

组合规则只允许 `requires_planning=no` 且恰好一个适配问题为 yes、另一个为 no。三个答案的最小顶部概率和最小分差均须通过对应路径阈值；任意冲突、unclear、失败或未知回执都回退。原始请求完整保留。历史、附件、政策、知识范围及确定性规则跳过逻辑不变。

本阶段候选位于 `experiments/jev-routing-optimization`，CLI 专用，不修改默认配置、现行 v2 策略或运行产品。生产计费边界仍拒绝新三问题协议；候选明确拒绝带产品 spend context 的调用。没有真实邮箱查询、客户数据出站或业务工具执行。暂不接数据库匹配特征，以免将提示结构变化与新增数据混为一个实验。

1. 将上一轮已暴露的 48 条合成题明确转为开发集，冻结唯一候选提示及阈值选择规则后，最多 48 笔 Jev 调用。
2. 仅用开发结果选阈值：概率 0.50–0.95、分差 0.05–0.50，步长均 0.05；要求观察到的错误放行数为 0，最大化正确放行数，同分优先更高概率、再更高分差。无合适阈值时禁用该路径。
3. 冻结新 60 条合成题、标签与选定策略后，旧 Jev 与优化 Jev 同题配对验证：各最多 48 笔调用和 12 条规则跳过。交替先后顺序，不是产品中串联两个路由器。
4. 一次请求包含三个问题，但会增加 token；不能把请求数相同描述为费用相同。保存原始 usage，报告输入输出量与请求耗时；不宣称完整业务收益。

新验证工程门槛（工程设定，并非用户逐值确认）：可用率至少 95%，固定/interpreter 正例各至少 50%，错误快速放行及规则违规均为 0；固定流程比同题旧 Jev 提升至少 25 个百分点，interpreter 覆盖不下降，请求 P95 不超过 2 秒。每类仅 12 正例，是初筛，不等于自然业务质量验收。

原始回执放入忽略目录，独占写入 started 后才能调用；未知/失败不重试，不换模型；连续三笔失败停止。调用前提交冻结清单，结果另阶段记录。若本候选失败，保留失败结论，不在新验证集反复调参。

参考：[TypeSafe 独立小问题](https://docs.typesafe.ai/introduction)、[Choice 描述与并行问题](https://docs.typesafe.ai/primitives/choice)、[输入状态](https://docs.typesafe.ai/concepts/state)。

## 新样本同题验证结果

冻结提交 `038f1c19` 已先于验证调用推送。最终结论：**固定查询覆盖明显改善，但候选整体未通过预设门槛，未进入运行产品。**

| 指标 | 旧 Jev（v2） | 优化 Jev（三问题） |
| --- | --- | --- |
| 有效响应 / 尝试 | 47/48 | 47/48 |
| 规则跳过正确 | 12/12 | 12/12 |
| 固定查询覆盖 | 3/12（25%） | 11/12（91.7%） |
| interpreter 覆盖 | 9/12（75%） | 8/12（66.7%） |
| 错误快速放行 | 0 | 0 |
| 成功请求 P95 | 992 ms | 1,196 ms |
| 有效回执输入 token 合计 | 33,913 | 67,330 |
| 有效回执输出 token 合计 | 2,574 | 5,456 |

固定查询提高 66.7 个百分点；三问题输入量约为旧版的 1.99 倍，成功请求 P95 多 204 ms。请求数相同不意味着成本相同；本轮没有执行完整业务链，不能声称整体节省费用或时间。原始 usage 保留于本地，表中仅统计可解析成功回执，不包含未知请求可能产生的用量。

唯一未覆盖的固定查询 F01 在两组都产生失败/未知回执，耗时分别 2,515 / 2,506 ms，接近 2.5 秒截止；没有自动重试，也没有将其算作成功。不能从目前仅保存的状态断言服务端是否完成。开发和验证合计 144 次请求尝试，142 份有效响应。

优化版未覆盖的四条 interpreter 正例 I02/I03/I05/I08，其原始三个判断均给出了正确方向，但至少一个必要答案的概率低于开发集选择的 0.90。组合后的门槛放行数因此下降；这不是证明模型已经正确处理实际批量业务，也不能依据已曝光的新验证题把阈值降低后宣布通过。

每组报告的 `gatePassed` 来自原有绝对门槛（各覆盖至少一半等）；**最终结果只以最外层 `gatePassed=false` 为准**，因为新增的同题 interpreter 不退步条件未满足。一个样本的差距不能证明总体能力退化，但足以使这一预先声明的工程门槛不通过。

检查结果：35 项定向测试、完整类型检查和相关 lint 通过；离线重算确认提示、样本、阈值及回执身份哈希没有漂移。[机器可读证据](evidence/jev-optimization-2026-11-09.json)。重算命令 `node scripts/run-tsx.cjs experiments/jev-routing-optimization/run.ts report` 不调用模型。
