# 当前决策记忆的有效期复核

`loadMemory` 对当前偏好与政策的 `valid_from`、`valid_until` 使用数据库检查时刻 `clock_timestamp()`。这也适用于最终 Skill 材料复核绑定到同一事务的读取，避免事务开始时间让已过期记忆继续有效，或让刚生效记忆继续不可见。历史双时间查询仍按其指定时点执行。

[实际数据库验收](evidence/ma24-g03-g09-memory-wall-clock-2026-10-17.json)在一个绑定事务内读取两条合成偏好，等待跨过有效期边界后再读。旧事务时钟仍早于到期时间，但当前读取已移除过期项、加入新生效项；已有决策记忆守卫拒绝旧快照。跨账号不可见，14 项守卫回归、类型/lint 和既有来源并发回归通过。

这证明读取时刻的有效性，不构成提交前的有效性租约。最终启用仍需在同一事务的最后检查中复核时效，记忆写入/共享政策并发和其他来源锁仍待完成。未调用模型、部署生产或开放自动启用。
