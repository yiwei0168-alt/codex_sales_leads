## 最短发布路径

1. 确定访问路径：优先已有受管理的 HTTPS 主机/域名或公司 VPN；明确是否已有服务器以及首批成员邮箱。账号密码和密钥只在目标环境配置，不进入 Git/聊天。
2. 冻结首批功能和服务版本。把单独的 Web 候选、数据库版本、必要 worker/模型依赖和功能开关写入同一发布单。未验收的自动发送、付费评测和高级流程保持关闭。
3. 在目标环境准备受限数据库账号、HTTPS、日志、备份存储与监控；创建新的空数据库，使用 `npm run db:migrate:pilot-fresh` 初始化至 135，核对内置不可登录占位账号外没有用户、业务文档为 0，且 136–140 未应用。数据库角色须由目标环境操作员单独配置；迁移凭据不得进入 Web 环境。
4. 为实际试用成员建立专门的测试账号，只写入虚构公司、线索和任务；先验证一次新库备份及恢复，再以两个账号验收登录、隔离、最小业务闭环、错误处理和退出登录。记录 Web 包指针、功能开关与停止写入后的回切步骤。
5. 先开放少量内部成员，再扩至首批团队。记录实际入口、版本、健康检查、问题反馈人和回滚触发条件。回滚时先停止新写入并检查迁移兼容性；不能把旧 Web 指针切回当成数据库回滚。
