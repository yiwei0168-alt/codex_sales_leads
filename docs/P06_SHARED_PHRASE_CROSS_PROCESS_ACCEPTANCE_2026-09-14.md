# 阶段129：共享短语评分请求的跨进程检查点恢复

在阶段128的实际评分 Agent 无损压缩基础上，运行 `node scripts/run-tsx.cjs scripts/verify-shared-phrase-score-checkpoint.ts`。脚本仅使用隔离合成公司、模拟模型响应和模拟业务保存适配器；图及 PostgreSQL `PostgresSaver` 为产品实现。父进程生成随机独立 thread，按 `seed`、`resume` 启动两个 Node 进程，最终清理该 thread。没有网络模型、搜索或邮件外发。

第一进程在评分阶段边界暂停，检查点存入 101 条原始当前证据、105 条角色事实、原计划、身份和既有 13 个**合成**额度；模拟模型调用和结果保存均为 0。第二进程按同一用户/动作/计划恢复，其他用户或动作被拒，证据及事实逐项与原值相等。当前 `LeadQualificationAgent` 从恢复内容构造完整评分请求，使用 `exact-shared-phrase-v1`，通过 DeepSeek 实际序列化的 61,440 字节预检；模拟模型恰好收到 1 次请求，评分结果 `scoringStatus=completed`，准备 metadata 随结果交给模拟保存适配器。国家或证据改变时计算出的缓存契约不同，恢复所得完成契约与预期相同。原有 13 个合成额度保留，评分前阶段执行次数为 0。

模拟输出的资格结果依确定性门禁计算，本案例最终合格为 0；脚本不伪造达标。跨进程恢复证明的是完整评分 Agent、编码、图检查点和模拟保存适配器的接线，不证明真实模型理解短语字典、真实供应商费用报告、产品结果 SQL 持久化或用户采用。不可压缩的任意大输入仍需完整引用的分阶段处理。P06、A11 和整体验收继续未完成。
