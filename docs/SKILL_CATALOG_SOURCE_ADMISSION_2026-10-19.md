# G09 可见 Skill 目录来源保护

候选快照读取整个可见 Skill 目录，因而仅锁原任务固定版本还不足以保护新增、发布或历史绑定变化。迁移 152 把 `agent_skill`、`agent_skill_version`、`agent_run_skill` 的写入接入现有 `skill-memory-global` 与账号来源锁；持锁证据读取在审核包、冻结和 Skill 行之前取得目录来源锁，并向材料/准备结果传递 `skillCatalogSourcesLocked=true`。它不是启用授权，`sourceRevocationsLocked`、生产资格和自动启用仍为 false。

普通账号私有写入取得共享全局与本账号排他锁；管理员、未设置账号的写入和 TRUNCATE 使用全局排他锁。行级触发器根据实际共享范围、归属及其他账号保留的历史绑定再核对，保护已由共享改为私有但仍在他人目录中可见的方法。其他账号的普通私有创建在没有排队全局写入时可继续，不声称全局写入排队后没有等待。

导入/版本变更、人工状态操作、首次任务绑定和经验草案在取得业务行锁前先申请写入许可。目标方法已共享或有外部账号历史绑定时，提前取得全局锁，避免先锁方法行再等待来源锁。任意特权 SQL 先显式锁行再写入仍可能被 PostgreSQL 按死锁中止；不能把这种中止当成验收通过。

新写入代码通过函数存在性查询兼容未安装 152 的旧库；旧库没有目录锁读取入口，内部持锁验收必须安装 152，缺函数时拒绝。检查元数据失败或已配置的写入锁失败均直接抛错。此兼容路径不授予旧库任何验收或启用资格。部署顺序应先更新并排空旧写入进程，再安装精确迁移和启用新的验收读取；本轮没有执行生产部署或迁移。

验收：48 项定向回归、类型检查和相关 lint 通过；全新 PostgreSQL 实测八类写入等待/释放、目录哈希稳定、其他账号私有创建继续、持锁事务内账号更新、旧共享历史绑定保护、降级账号下特权版本改写保护及无新增表写权限。首次数据库夹具因应用角色不能锁他人私有行而失败，现改用既有受限固定方法锁函数验证，没有放宽 RLS。新夹具与其他 pristine 检查混用会在 Docker 初始化前拒绝。固定提交 `600c371c` 的完整五类组合随后退出 0，前瞻两臂、组合材料、目录/固定来源锁及开发审核链路通过，临时容器和源码快照已清理；该提交不包含后续准备期记忆守卫或原件下载修改。[结构化证据](evidence/ma24-g09-skill-catalog-source-admission-2026-10-19.json)。
