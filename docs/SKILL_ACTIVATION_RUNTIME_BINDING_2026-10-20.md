# G09 自动启用绑定的运行指纹

对应既有MA24-06。自动启用绑定增加必填 `runtimeHash`，取自已核对的冻结计划；最终适配器同时核对readiness的当前完整身份摘要与冻结身份相同。调用者不能提交指纹或绕过readiness。

读取、模型/UI列表、运行中和依赖方法复用的 `skillActivationCurrent`，在业务来源与评测日志重建前后分别重新计算当前源码/配置/Node版本/平台/架构指纹，与绑定比较。指纹不可读、变化或重建期间变化均拒绝。账号替换、旧自动绑定缺指纹也拒绝；无绑定的人工Skill仍沿原路径。

该指纹沿用既有 `skillSourceRuntimeHash`，包含源码、package/lock/tsconfig、Node与平台，不是已加载机器码或安装依赖字节的证明；登记包、运行边界及最终生产等价性仍需独立核验。两次读取也不使磁盘不可变；正式只读运行包与完整来源保护仍待联合验收。

52项定向测试、全项目类型和5文件ESLint通过。全新162隔离数据库退出0：在受限账号绑定保持当前时，新增不执行的随机JSON源码标记使真实指纹变化，实际读取、模型/UI列表、运行中及依赖方法均拒绝；删除标记恢复相同指纹后只恢复组件可用性，不重新启用或生成新证明。标记已清理，既有生命周期、来源封闭、期限和COMMIT双结果回归也通过。本轮正向资格仍为明确的readiness替身，不创建human质量批准或生产资格。[终态证据](evidence/ma24-g09-activation-runtime-binding-2026-10-20.json)。

该阶段不修改数据库迁移，不开放自动启用，不部署。新增绑定使旧自动证明缺字段时失效；既有固定b4e75e97镜像不包含本变化。G09的来源总门槛、运行等价性、真实登记联合正例和真实质量仍未完成，G14–G20及上线继续暂缓。
