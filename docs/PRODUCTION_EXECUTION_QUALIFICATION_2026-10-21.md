The producer combines server-owned reader results in the owning transaction:

1. The latest policy has passed, including the existing independent human judgments and all five required categories; artifact, review, plan and current runtime identities agree.
2. Current reconstructed materials and locked original journals cover every expected original task and evaluation arm.
3. Every original/evaluation/fallback transport has an authenticated process claim matching a retained current runtime package, executable and Node binary; source/dependency/ESM pairing and collector provenance pass.
4. All evaluation tasks have bound execution policies. Prospective tasks use registered live reads and current-source revalidation. The policy manifest is part of the task and acceptance ledgers.
5. Evaluation receipt count equals the complete frozen model-attempt ledger count. Original/evaluation counts sum to the complete transport count, and every transport has a package binding. Extra frozen attempts and missing fallback coverage block qualification.
6. The experience/source validity fence and source-protection preparation are current. Final activation separately retains its actor/lease, instruction-only eligibility, catalog, deferred source/review/declaration guards and atomic effect/receipt/audit commit.

No tool or HTTP caller supplies this composition. Missing components produce explicit blockers. The final activation schema requires scope/hash and the new process/policy evidence in addition to the previous qualification flag. Its audit event includes the scoped execution proof hash; the full activation proof and existing source ledger remain bound to subsequent use.
