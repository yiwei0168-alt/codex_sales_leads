# G09 本地经验来源的数据库锁

## 143 原始记录保护补强

迁移 `143_skill_memory_origin_locks.sql` 替换同一内部函数，从当前账号观察的收据派生原始会话、任务和用户消息 ID，先锁账号及这些原始记录，再锁观察与冲突。原始记录使用 SHARE，阻止内容、归属及状态更新，并允许普通外键插入。调用方仍须在同一事务中执行既有来源守卫复查，保持锁至最终操作结束。

[实际一次性数据库验收](evidence/ma24-g09-memory-origin-locks-2026-10-16.json)观察到账号、会话、任务和消息四个更新等待持锁方，释放后全部继续；原始消息改变后复查拒绝。迁移重复安装、纠正/失效/冲突并发、跨账号拒绝、过期检查、类型与 lint 均通过。没有增加表写权限、生产修改或模型调用。下方关于原始记录尚未锁定的描述是 142 阶段历史限制，已由 143 关闭；其他来源家族与最终自动启用仍未完成。

当前已接入 `readLockedSkillAcceptanceEvidence`：取得 Skill 更新锁后，从已存版本的 `sourceObservations` 派生并排序 ID，验证来源标签/账号/内容哈希，再取得观察与冲突锁并重新运行来源有效性守卫。普通导入包不调用此函数；缺迁移或锁后来源变化时拒绝。来源有效期改用检查时刻的 `clock_timestamp()`，不沿用可能已过时的事务开始时间。

这里持有的是观察与冲突行锁。原始报告消息、任务及账号状态会被守卫重查，但本接口尚未分别锁定这些行；不能据局部锁状态推导全部来源在提交前不可变化。

[接线验收](evidence/ma24-g09-memory-source-lock-wiring-2026-10-16.json)通过 32 项回归、类型/lint 和实际存储引用链检查；纠正/失效发生后及事务开始后来源过期均被拒绝。引用是合成的未核实用户经验，不是方法质量证据。本阶段未执行完整本地经验 Skill 的自动启用场景，也未完成其他来源类型的最终保护。

迁移 `142_skill_memory_source_locks.sql` 新增内部函数 `lock_skill_memory_sources(uuid[])`。它只锁定当前账号拥有的观察记录，并锁定引用这些观察的已有冲突记录；返回记录数，不返回来源正文。单次最多 100 个不重复、非空 ID，空数组返回 0，缺失或其他账号的记录一律拒绝。

观察记录的纠正和失效由新行的外键表达，普通共享锁不足以阻止这类插入。函数对原观察使用更新锁，使新纠正/失效/冲突插入的外键检查等待；同时锁定已有冲突行，阻止仅改变状态、无需重新检查外键的更新。

函数使用固定 `search_path` 的 SECURITY DEFINER，公开执行权被撤销，仅应用角色可调用；没有增加应用角色对观察表的 UPDATE 权限，采集角色也没有执行权。调用方必须在既有账号隔离事务中持有锁，并在锁后重新检查来源是否有效，不能将“取得锁”当作来源质量或启用批准。

[实际新库验收](evidence/ma24-g09-memory-source-locks-2026-10-16.json)观察到纠正插入、失效插入和已有冲突重新打开三个事务均等待持锁方，释放后全部完成；跨账号、重复 ID 和空参数拒绝，重复安装迁移通过。仅在通过 135 的一次性库精确安装本迁移，未安装延后的 136–140，也未修改生产库。

当前只完成本地经验观察/冲突这一类锁实现；尚未接到最终启用事务，也不覆盖全部知识、邮箱、客户时间线或其他记忆读取来源。完整材料重建与生产认证仍需分别验收。真实模型调用和自动启用均为 0。
