# 恢复链唯一保存公司对账（阶段88）

任务详情对同一用户、国家和原任务的恢复链进行只读对账。一次数据库快照关联原任务及全部恢复子任务、各自完成的运行和真实入库的 `selected` 评估；公司域名归一化后按唯一身份计数。页面同时显示原目标、唯一保存数、剩余缺口、重复保存槽位和未完成任务数。父任务和子任务读取同一恢复链结果，子任务自己的运行数量仍独立展示。

已完成任务的运行、结果计数、国家或选择记录缺失或矛盾时，唯一数量和缺口为“无法核对”；不能从缺项反推零。未完成子任务只计入待完成数，其尚未保存的候选不进入已核实公司数。单独任务没有恢复链，不增加汇总。该口径不改变原评分、历史结果、预算、搜索范围或冻结哥伦比亚测评。

验证：882 项测试 / 194 文件及生产构建通过；隔离 PostgreSQL fixture 模拟已完成恢复运行、结果与实际选择记录。第二个保存槽位使用同一域名后，唯一保存仍为 1、槽位变为 2；已完成任务缺少匹配运行或选择时返回未知。跨用户读取拒绝；合成选择、任务、检查点及费用记录清理。恢复链汇总写入聚合操作遥测，记录输入任务数、有效/下游展示输出、耗时、丢弃原因、重复槽位与优化机会；刷新同一快照只保留一条，用户实际采用仍未知。未产生模型、搜索、邮件或真实付费调用。

本阶段只核实持久化的唯一保存数，不证明恢复执行后的模型质量、最终填满目标或真实业务闭环。长期暂停后的全部依赖有效性及 A11 最小真实运行继续验收。
