# 本地 LangGraph 网络权限恢复

2026-10-08，用户反馈产品显示“主模型暂时不可用”。在用户指定账号范围内检查当天任务：两次主模型尝试均记录 `paid-outcome-unknown`，任务保留为 `partial`，尚未执行邮件工具。

同机对照检查发现，受限执行环境请求 OpenRouter 公共模型列表失败，底层代码为 `EACCES`；正常权限下同一只读请求返回 HTTP 200，配置的 `z-ai/glm-5.3` 仍在列表。正常权限下密钥检查也返回 HTTP 200，未打印密钥或响应内容。此前“必须改走代理”的初步判断已纠正；MA18/MA19 的 GLM 直连规则继续适用。

停止本轮启动的受限 LangGraph 进程，以正常网络权限重新执行 `npm run langgraph:dev`。本地 `/ok` 返回 200；`npm run langgraph:verify-routing` 通过，4 个请求、1 个健康输出、2 个预期 Schema 拒绝，外部模型调用为 0。修复验证覆盖服务、网络和认证，尚不构成真实模型回答或邮件简报成功的证据。

恢复原邮件简报任务的操作首次被自动审批拒绝，理由是指定邮箱授权诊断，不自动授权恢复会读取邮件并可能调用付费模型的流程。用户随后在 `call_b865e3568ac649f186766bce86524e19` 明确选择“恢复原邮件简报任务”。执行前检查发现任务已在运行，因此未重复排队。真实主模型随后多次成功返回并完成工具调用；任务最终返回邮件同步不可用说明，不能当作目标日期简报已完成。历史失败收据未改写。

## 邮件连接的后续阻碍

账号范围内同步日志显示“邮件服务器解析到了非公网地址”。系统及普通 UDP DNS 将阿里企业邮箱 IMAP 域名解析为 `198.18.0.123`，属于应拒绝的非公网地址。通过本机代理向阿里公共 DNS 的 HTTPS JSON 接口查询同域名，得到公网地址。新增显式配置 `MAILBOX_DNS_MODE=alidns-doh`；默认仍为 `system`。HTTPS DNS 仅传递服务器域名，固定访问 `dns.alidns.com` 并沿 MA19 固定 HTTP API 规则走 `MODEL_PROXY_URL`，4 秒超时、禁止重定向、校验问题域名/记录类型/别名链及公网地址，连接继续固定解析后地址并校验证书域名。本机已启用该模式，环境文件不提交。

DNS 解析后，授权的指定日期 INBOX 同步在 IMAP 993 TLS 握手阶段返回 `ECONNRESET`。另以公网地址及原域名各做一次经本机代理的无凭据 TLS 探针，同样返回 `ECONNRESET`；CONNECT 成功不代表 IMAP TLS 成功。尚未恢复邮箱传输，未取得目标期间邮件，也未声称生成该期间简报。没有关闭公网地址保护或 TLS 证书校验。

验证：邮件地址校验、SMTP 传输、HTTP 路由三组共 17 项测试通过；定向 ESLint 通过。覆盖 HTTPS DNS 返回私网/fake-IP/非法地址、错误状态、截断响应、域名不匹配、无关联记录及别名链。真实同步失败记录保留在当前账号，不提交邮件正文或凭据。

后续在本机启动运行时，应确认进程具有既定提供方所需网络权限；首页和 LangGraph 健康接口成功不足以证明外部模型可达。优先使用公共元数据及认证状态检查，再区分真实业务验证。
