# 本地 LangGraph 网络权限恢复

2026-10-08，用户反馈产品显示“主模型暂时不可用”。在用户指定账号范围内检查当天任务：两次主模型尝试均记录 `paid-outcome-unknown`，任务保留为 `partial`，尚未执行邮件工具。

同机对照检查发现，受限执行环境请求 OpenRouter 公共模型列表失败，底层代码为 `EACCES`；正常权限下同一只读请求返回 HTTP 200，配置的 `z-ai/glm-5.3` 仍在列表。正常权限下密钥检查也返回 HTTP 200，未打印密钥或响应内容。此前“必须改走代理”的初步判断已纠正；MA18/MA19 的 GLM 直连规则继续适用。

停止本轮启动的受限 LangGraph 进程，以正常网络权限重新执行 `npm run langgraph:dev`。本地 `/ok` 返回 200；`npm run langgraph:verify-routing` 通过，4 个请求、1 个健康输出、2 个预期 Schema 拒绝，外部模型调用为 0。修复验证覆盖服务、网络和认证，尚不构成真实模型回答或邮件简报成功的证据。

恢复原邮件简报任务的操作被自动审批拒绝，理由是指定邮箱授权诊断，不自动授权恢复会读取邮件并可能调用付费模型的流程。已请用户明确确认；截至本记录，原任务未被本次诊断恢复，历史失败收据未改写。未更改产品代码、模型选择、网络分流规则或冻结集候选。

后续在本机启动运行时，应确认进程具有既定提供方所需网络权限；首页和 LangGraph 健康接口成功不足以证明外部模型可达。优先使用公共元数据及认证状态检查，再区分真实业务验证。
