# 记忆写入的来源保护锁顺序

G03 迁移 154 的抽取路径在记忆写入前持有来源 admission。审查发现，旧观察/纠正/撤销/版本写入入口可能先拿记忆键或目标行，再由数据库触发器等待 admission；与新路径的反向顺序可形成等待环。

新增 `lockMemorySourceAdmission`，在这些入口取得记忆键、目标锁或版本行锁之前执行：先取得全局共享锁，再取得账号排他锁；管理员或全局范围操作直接取得全局排他锁。使用与迁移 148/154 相同的 advisory key，不新增迁移，也不依赖新增函数存在。

已接入普通观察、显式/消息纠正的实际纠正函数、观察撤销、旧版保存和旧版撤销。旧版撤销可能触及全局来源，故在锁行前取得全局排他保护；观察撤销桥接旧版时也提前取得该锁，避免嵌套后升级。

## 验收

79 项定向测试通过。实际隔离克隆中，持有迁移 154 来源锁的账号启动另一条观察、纠正、观察撤销、旧版保存或旧版自动记忆嵌套撤销。五例均观察到对 admission 的等待；持锁事务随后使用 2 秒 lock_timeout 成功写入同一记忆键，提交后等待者完成。模型/网络调用为 0，合成数据清理完成。[收据](evidence/ma24-g03-memory-admission-order-2026-10-19.json)。原七类来源变化验证及显式/自然纠正/撤销回归仍通过。

本次未声称复现生产死锁或排除所有数据库等待环。它验证指定入口的锁顺序及受控并发序列；长时间负载、进程崩溃、全库迁移并发、最终产品镜像和生产仍待验。旧版撤销会在短事务内使用全局排他锁，实际负载下的等待容量仍须观察。

当前新代码尚未进入已验证的 `25f5acd3` 镜像和签名组合快照；来源/质量/自动启用门槛不变。普通抽取仍须先安装迁移 154，正式 Worker 和内网上线继续暂缓。
