# Stage 209: P06 singleton chunk append-only checkpoint

The singleton chunk planner now derives a disjoint checkpoint stream fingerprint from the full candidate source fingerprint, original unit kind/ID and whole-text SHA256. The request carries both the original candidate dependency and the derived stream identity. This lets different long units and ordinary fact phases share the existing append-only `lead_qualification_phase_checkpoint` table without key collisions or a schema migration. Changing the middle of a source changes the stream, cache contract and paid-request fingerprint even if the first chunk text remains unchanged.

`productQualificationSingletonChunkCheckpoint` saves only a validated complete chunk response under user, workspace, action, country, candidate, stream, chunk index, execution contract and exact paid HTTP fingerprint. Private requests must carry the same workspace scope as the checkpoint. It checks requested and actual provider/model identity, the full chunk schema and original citation closure. Missing rows are not permission to repeat an unknown paid request; route changes and concurrent completion stop before a new call. The existing billing recovery guard can recognize an exact reported complete chunk via the same phase-table paid fingerprint. No historical row was rewritten and no new tariff, route or model was enabled.

An isolated real PostgreSQL verifier saved two synthetic chunk outputs, loaded one in a separate process, checked duplicate save idempotence, rejected changed output and wrong provider, blocked a changed route, and confirmed altered source content missed the old checkpoint. Cross-user and cross-country reads returned none; the application role could not update the append-only row. Fixture rows were removed and absence was checked. Full **1,030 tests in 208 files**, TypeScript, focused ESLint and production build passed. The read-only budget stayed USD12.324404/30, with six historical unknown bills, zero unsettled calls and zero new paid provider calls. No model/search/mail/customer task ran.

This checkpoint component is not yet called by `LeadQualificationAgent`. It validates and persists chunk outputs, but has not established complete ordered chunk coverage, bounded synthesis or final scoring for a long singleton.
