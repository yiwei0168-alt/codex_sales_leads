# P06 超大单家公司结构化压缩与暂停验证

阶段60，范围为B07/B26已确认的“保留关键信息的压缩/分阶段处理；仍无法满足时保存进度和明确原因”。本阶段选择无模型、无信息损失的结构化压缩，不新增搜索、补证或付费预处理。

原实现仅复用完全相同的长标题/摘录，独有证据没有对应表示。现对超限单公司的证据及原子事实采用`exact-field-table-v1`：同构记录的字段名保存一次，各行保留完整值及原顺序。所有原文、URL、证据ID、嵌套数组/对象、null、否定与unknown状态仍在请求中。字段缺失与null不能混同，因此异构记录不强制表化；已有表字段不覆盖。普通未超限请求不变，最多五家公司、评分/路径模式及输出Schema不变。

先尝试既有重复文本字典；仍超限时分别比较原记录表化、字典记录表化的完整发送体，选择更小者。字节测量继续使用主模型及获准备用路由的最大实际序列化大小，说明文字也计入。编码和事实变化进入实际请求/缓存身份，不把旧表示缓存当成新契约命中。模型必须按列名恢复对象，再执行原始角色/评分规则；结构恢复的确定性证明不等于已证明模型遵从或评分质量。

压缩仍不够时，既有`LeadRequestTooLargeError`保持候选未完成并阻止传输，不输出业务拒绝、低分或合格结果。未引入自动删除证据、模型摘要或超限后自动重试。若未来仍需处理超出此表示能力的载荷，可继续在B26边界内补分阶段方案；不能声称本阶段支持任意大小输入。

验证证据：

- 100条互不重复证据及100条事实，压缩前真实请求超过36864字节，压缩后容纳；列/行反解与原记录深度相等，原输入不变，原指令及输出Schema保持。
- 真实DeepSeek序列化器与包装器使用合成传输，发送体与预检一致；事实变化使缓存身份失效。缺字段/null及已有元数据不覆盖；无法压缩的单长文本仍在调用前拒绝。
- LangGraph MemorySaver在实际超限预检处停止于`correct_candidates`：候选、证据和先前费用保留，评分/最终保存未执行。重建图并使该阶段可处理后从同一边界恢复，搜索/补证各仅一次。此为合成依赖及内存检查点，不冒充跨进程PostgreSQL或真实模型验收。
- 63项相关测试、831项全量测试/181文件、生产build含类型检查通过。随后加强超大原文检查点断言，18项图测试再通过。首次单独typecheck发现新测试回调泛型缺注解，修正后生产类型检查通过。生成文档检查首次提示源码哈希过期，刷新后check通过。

遥测：请求准备附带编码、原始/准备后最大路由字节、证据与事实条数；校正和评分成功响应的用量记录将其写入阶段metadata及检查点，沿用既有数据库JSON持久化。该元数据不送模型、不含正文，也不声称是token节省或实际成本节省。费用/延迟/重试/有效/下游计数继续沿用原阶段观测；没有成功响应的准备不能推定为下游使用。压缩过程本身0 API、0 token、0付费。本阶段无schema迁移、无冻结实验改写；整体验收保持未完成。
