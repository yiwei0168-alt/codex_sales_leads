# Durable normal scoring response recovery

This stage repairs the normal lead-qualification response path under existing checkpoint/replay rules. It does not change the lead-value rubric, role scope, model selection, output cap, company evidence or qualification gates.

Root cause evidence: routine batches passed their provider response into business-schema validation before any raw response checkpoint existed. A malformed or omitted singleton then entered a singleton repair that could serialize to exactly the same primary request, so the paid-request guard correctly refused it. One historical SG-02 response has HTTP 200/stop but no recoverable response original or validated assessment cache. Its content cannot be reconstructed or certified from token/HTTP metadata. Offline reconstruction of original request dependencies matched that completed request to one specific candidate only; the other request has an unknown outcome.

Changes:

- The owned lead workflow explicitly enables durable qualification responses. DeepSeek stores a completed response before content/schema validation in an append-only encrypted checkpoint, bound to owner, action, task and exact paid-request fingerprint. Original HTTP request bodies, authorization headers and credentials are not stored. Key/ownership/read/write failures stop new work rather than infer a cache miss.
- Response encryption uses AES-256-GCM with per-user HKDF derivation from the existing protected runtime key and owner/action/request associated data. Migration 174 adds owner/action RLS and application SELECT/INSERT-only privileges.
- A completed response is reused before any new transport call. Cached use does not re-count provider tokens or calls as new usage. Invalid model content remains subject to the existing strict business schema; it does not become a qualified score.
- A singleton schema repair adds an explicit, deterministic repair instruction to its request. It therefore cannot be an unchanged repeat of its primary singleton. Its exact response and request cache contract are retained. The original evidence and rubric stay intact.
- Historical recovery of the unavailable original requires a separately recorded candidate-local recovery marker bound to the exact owned completed request receipt. The marker makes a new, explicitly labeled regeneration request, not a claimed restoration of the missing original. The completed old receipt remains unchanged; no replay guard is disabled. Other saved sources and corrections remain unchanged.

Verification: 81 workflow/checkpoint tests, 54 provider/replay tests and 19 repository checks passed; TypeScript and targeted lint passed. A malformed-singleton fixture reproduces the need for distinct repair, succeeds with two distinct requests, then reuses both responses after agent/provider reconstruction with zero additional transport calls and zero new usage entries. Real database rollback checks passed owner encryption/readback, peer read denial, peer foreign-action insert denial and update denial. The live historical fingerprint preflight found exactly one affected candidate and no existing raw checkpoint; no model call was used for that preflight. Future runtime and actual recovery results remain separately recorded.

Marked historical-response recovery uses batches of at most two companies, preserving all inputs and the unchanged rubric; ordinary task batch sizing is unchanged. This limits recovery response size after the former four-company request reached its 120-second deadline. Strict recovery preflight also recognizes the new owner/action/fingerprint-bound encrypted checkpoint, while unknown/unretained responses remain subject to existing guards.

Actual recovery completed scoring of five candidates, including a single-candidate schema repair for overlong rationale text; independently valid peers were preserved. Four newly completed scoring responses were encrypted and retained. Required secondary/judge review completed. The run persisted one qualifying result out of the requested three, then stopped with role-unresolved: two other candidates still have unresolved business roles. No new market search or evidence collection was performed during this recovery. Job completion is a partial delivery, not target attainment, business acceptance or market exhaustion. The unavailable historical response was not reconstructed; its new replacement request and old receipt remain distinct.
