# 按原设计的搜索与评分验收方案

规则 ID：`LEAD-STRATEGY-ACCEPTANCE-01`。用户于 2026-10-30 明确要求按原设计准备验收，产品搜索逻辑也沿用原设计，并核对评分体系。该决定取代 2026-10-29 将“各类渠道各 3 家”解释为 13 个角色独立任务的实施口径；原任务、调用记录和已交付结果保留，不改写成合并策略已通过。

英国首轮按以下六组各最终合格 3 家准备，总计 18 个组内名额；组内各角色没有单独配额。Agent、Brand Owner、OEM/ODM 继续仅在明确要求时另开，不自动纳入本轮。这里的 18 是准备目标，不是已搜索或已验收数量，也不是跨组去重后的公司总数。

| 用例 | 合并策略 | 角色范围 | 首轮轨道（英国、auto、小目标） | 后续补充条件 |
|---|---|---|---|---|
| SG-01 | 分销 | Distributor / VAD | strategic | 合格缺口下按互补机制补充 |
| SG-02 | B2B 转售 | VAR / Dealer / Reseller | national-b2b / local-b2b | 按全国与本地商业动作补证、去重 |
| SG-03 | 零售与电商 | Retailer / E-tailer | etail / retail-national | 最终合格不足的后续轮才补 retail-local；明确 national 时不扩大范围 |
| SG-04 | 集成与托管服务 | SI / MSP | national-complex / local-smb | 区分项目交付、设备选型与持续托管证据 |
| SG-05 | 安装工程 | Installer | local-regional | 沿当前覆盖范围与缺口条件补充，不凭安装推定采购权 |
| SG-06 | 运营商 | ISP | strategic-national | 区域 WISP 仍按明确覆盖需求或原策略条件启用 |

执行顺序与材料：

1. 先复核已交付的原 Distributor-only 三家公司。允许复用仍有效的公司身份、证据和评分，保留原任务范围；不因旧任务完成就把 SG-01 或整套方案标为通过，也不要求为了涵盖 VAD 人为凑一家公司。
2. 每组执行前从当前生产路由生成轨道清单，逐条记录实际执行/条件未满足/提前达标/供应商失败。配置中有工具不代表实际调用；不强制执行所有工具或凑足多轮。
3. 核对搜索候选、独立公司、范围内角色、证据可用公司、评分完成公司、必要复核完成公司和最终保存公司，分别计数。错类只在本次请求允许范围内转移；跨组出现同公司要声明复用关系，不伪装独立新增贡献。
4. 逐家打开原始资料，检查公司身份、英国业务、真实角色、网络产品/客户场景、采购或选型影响。缺失、推断与事实分开，联系人、合作意愿和 OEM 需求不能凭角色推定。
5. 逐家复核七项评分理由及引用、确定性总分、合作路径、账户等级和未知项。技术执行通过与用户认定有业务价值分别记录。少于 3 家时保留缺口和真实停止原因，不降低标准。
6. 每组完成业务复核后再推进下一组。合成回归覆盖失败恢复、去重、条件跳过及冲突；真实任务没有触发某条件时，仅标记该条件本轮未观测，不发起重复付费工作来补齐表格。

验收记录字段：用例/任务/国家、合并角色范围、目标、路由与实际工具状态、补搜原因、纠正/转移/去重记录、证据版本、分项与总分、必要复核状态、已保存结果、缺口/停止原因、用户逐家判定。具体账号、公司、任务标识和业务回答仅保存在本地私有材料，不进入公开仓库。

## 搜索与评分核对结果

| 项目 | 原规则及当前核对 |
|---|---|
| 搜索分类 | 六组常规合并搜索；13 个角色用于角色识别及评分锚点，不是 13 项默认独立搜索。4 个界面展示分区也不替代搜索分类。 |
| 工具与轨道 | 生产沿用 hybrid search v1.7.0 配置的类别/市场/条件路由；Tavily 只用于必要取证。Gemini Product 不与重合机制例行重复。 |
| 搜索纠偏 | 移除验收脚本的 13 角色独立目标和强制 mixed；恢复英国 auto 零售在最终合格缺口后开启本地轨道的接线。新路由上下文纳入轮次检查点契约，旧无缺口契约保持原哈希；不自动重放历史不兼容检查点。 |
| 线索价值 | policy v2.0.0，产品与场景 50（产品家族 25、客户/场景 15、定位 10）、路径与采购影响 15、同角色规模/覆盖 15、执行赋能 10、机会风险 10。模型判断子项，程序限幅并求和。评分策略和权重本轮不改。 |
| 产品匹配 | 采用最适合的启用产品轨道；全产品组合模式仅明确任务启用，不因专注 SMB 或集团无关业务稀释适配。 |
| 主角色 | 依据校正后的可观察商业行为；不沿搜索通道强制主角色、不恢复“优先向上”。未完成/Hybrid/Unresolved 不伪装完成评分。 |
| 合作路径 | 保留原五类，最多两条；路径权重 30/25/20/15/10，由程序求和。低于 65 的路径不能冒充达到正常推荐阈值；全部低于 65 时只展示最高一条。 |
| 账户等级 | 分销等级与下级渠道等级分开；一级分销不使用 KA，等级不反向增加分数。 |
| 未知与资格 | 未找到资料不是否定事实；未知规模不是规模小。资格门槛、当前证据绑定、确定性证据上限继续生效。 |
| 升级与复核 | 显著可解决的问题、预计总分至少改变 8 分或关键状态变化才支持升级；低置信度、Top-N、普通 warning 和随机抽检不能单独触发生产升级。修复默认复核 5% 与策略 0 的偏差，移除凭 warning 关键词扩张复核；关键门槛矛盾、原子证据冲突和 Pro/升级后关键未知仍复核。用户明确选择的独立研究审核及测试夹具可显式请求审核，不能混称自动抽检。 |
| 已完成结果 | 真实原任务的保存评分版本、校验和、权重与当前 policy v2.0.0 一致；本次只读核验，不重算历史分数。关系补证原始判断及局部私有证据收据保留。 |

此表核对配置、请求/算分代码及测试覆盖，不证明所有模型在所有真实公司上都按规则正确判断。模型服务商/具体模型按当前配置及已授权替代路由运行；评分规则对齐不等于恢复所有历史模型型号。新六组的真实路由执行、公司质量和用户采用均另行验收。

验证：13 文件 160 项测试、TypeScript 和定向 lint 通过（保留两条既有 unused-variable warning）。覆盖合并类别、市场轨道、条件工具、成熟市场补本地接线、轮次契约、角色评分、路径、账户等级、默认零抽检及关键复核。实际评分政策只读校验通过；本阶段没有发起新的搜索、评分、盲审或邮件发送。部署状态在阶段完成记录中追加。
