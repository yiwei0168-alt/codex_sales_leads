# 分层质量反例与失败进度验收（阶段 242）

## 结论

阶段 239 定义的受控产品层验收已收尾。阶段 241 已证明同一隔离动作可从两轮自然语言计划、确认、LangGraph 检查点恢复、实际 Agent 序列化与校验逻辑，到 PostgreSQL、任务 API 和生产桌面／移动页面仅保存 1 家复核完成的公司。本阶段补齐质量反例、失败语义、恢复和界面进度：

- `review-failed`、`targeted-research-required` 或缺失必要复核不再被计为已接受，也不再被误分类为 `qualified-shortfall`；图停在 `processing-incomplete`，不继续搜索补数、不生成 handoff、不保存国家结果。
- 用户确认恢复后，已完成的搜索、证据、校正和主评分直接复用，只重进必要复核。已付费的复核子请求仍使用精确合同检查点；未知费用会在恢复前阻止，不自动重放。
- handoff 的策略就绪与邮件就绪现在都要求复核状态为 `not-required`、`secondary-confirmed` 或 `judge-resolved`，与最终持久化口径一致。
- 检查点进度新增 `pendingReview`；任务页面同时显示待校正、待评分、待独立复核数量。测得的 0 与未知仍分开，三个阶段数不相加冒充唯一公司数。

因此，本轮可写为“受控产品层分层验收完成”。真实 Terra 语义、完整供应商账单／现金成本及原整体验收仍明确未通过；不把受控传输结果写成真实供应商闭环。
