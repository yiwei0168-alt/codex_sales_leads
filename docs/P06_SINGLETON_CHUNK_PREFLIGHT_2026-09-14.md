# Stage 208: P06 exact-wire singleton chunk preflight

`qualification-singleton-chunks.ts` adds a pure planner and output validator for one oversized corrected finding or source. It partitions the **entire original text** at Unicode code-point boundaries, measures each proposed `lead-qualification` request with the actual provider wire-byte function, and keeps every chunk at or below the current 57,344-byte fact-phase ceiling. Every request carries the original unit ID, original evidence IDs, whole-text SHA256, source fingerprint, country, model, chunk index/count and exact code-point offsets. The planner verifies ordered reconstruction equals the original text. A single code point that cannot fit the request contract fails before transport as `LeadRequestTooLargeError`.

The new strict chunk-output schema accepts only matching unit and chunk identities and original citation IDs. A material interpretation requires at least one cited original source; swapped chunks, foreign citations and uncited material outputs are rejected. Private chunk planning requires a tenant scope, but the DeepSeek wire/cache/paid hashes intentionally describe only the external request. Future checkpoint persistence must also key by user/workspace and country to enforce isolation; the planner alone does not provide that boundary. The prompt says that one segment cannot corroborate an entire source or upgrade an eligibility gate. No scoring threshold, route, tariff, provider call or historical assessment changed. **This is a standalone preflight component, not yet wired into the qualification agent, phase checkpoint or final synthesis.** Long critical or unlinked singletons therefore still remain technically pending in the current product until that integration and full regression are complete; this stage is not P06 acceptance.

Validation: a synthetic long critical finding with multibyte text produced multiple requests under the real DeepSeek byte contract and reconstructed exactly; a middle-text change altered both cache identity and paid-request fingerprint even for an unchanged first chunk. Synthetic swapped/foreign/uncited outputs and an oversized identity failed closed. The private-scope case verified scope is carried separately from equal paid-wire hashes; SQL tenant isolation remains to be tested after integration. Four focused tests, all **1,030 tests in 208 files**, TypeScript, focused ESLint and the Next.js production build passed. No model/search/SMTP call, database write or customer job occurred.

Efficiency record: four synthetic planner/validation inputs produced four usable local verification outcomes, all used to check the intended preflight contract; downstream **product** use and real qualified output remain zero/unknown because integration is pending. Model tokens, paid API credits, cash, external retries and real provider latency were zero/unknown; focused tests took about one second and full tests about twenty seconds. Three intentionally invalid synthetic outputs were rejected, not business leads. The next optimization step is to persist chunk outputs under exact paid identities plus tenant keys, require complete ordered coverage, then synthesize bounded interpretations while preserving uncertainty and the original fact/evidence snapshot. Only then can an oversized singleton enter final scoring safely.
