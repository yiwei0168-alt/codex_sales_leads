## 现有结构中的具体发现

1. Provider 发送稳定 system（含输出 Schema），user JSON 次序为 `task -> promptVersion -> evidenceIds -> input`。input 是 `instructions -> market -> cudyFitBrief -> candidates -> scoringRubric`。因此固定任务指令之前已遇动态证据 ID，完整固定 rubric 又位于动态候选之后；不是“完全没有缓存”，system 仍可构成固定前缀，但后面固定内容难以连续复用。
2. 明确重复字段：rubric 顶层 `policyKey`/`policyVersion` 与嵌套 policy 标识重复，`dimensions` 与 `policy.weights` 相同；instructions 又用自然语言重复主要权重。checksum 是不同的审计功能，不应与版本简单视为重复。是否删除某处表达须看它对模型的强调作用。
3. 完整 policy 内含模型不输出的账户等级枚举/80和75阈值、元数据及程序配置。模型同时被告知等级由程序计算且不能影响分数。这里有可投影空间，但“KA 不用于一级代理”“等级不影响评分”约束仍须保留。
4. 不是可任意删除的重复：instructions 中未知规模中性 8/15、采购影响封顶、按主角色比较、同主体目标国家门禁等关键说明不能仅靠 policy 的一般字段替代。policy 的角色 scorecards、产品轨道和 subweights 也不能只用总权重替代。
5. 潜在表述不一致需审阅：完整 policy 的 eligibility required 包含 viable-cooperation-path，但 score-only 指令不生成路径并改评采购影响。应明确“无需生成路径对象，但仍判断商业影响/采购适配”，不因精简把采购影响要求删掉。历史 freshnessDays 与用户一年提醒分属证据策略/界面提示，不能只因两个数不同就判重复或自动修改。
6. Provider 当前 usage 归一化只保留 input/output/reasoning/total，未保留 cache-hit/cache-miss；无法从现有离线报告判断实际命中或缓存节省。
7. 已有公共角色矫正结果缓存：公司域名＋国家＋公共证据指纹＋prompt版本＋角色体系版本，命中后重绑定当前证据 ID；不是没做缓存。当前依赖指纹未显式包含模型、queryRoles/missingEvidence 等请求输入，应先审阅这些输入如何影响结果与兼容性，再扩展复用，不直接降低失效条件。
8. 在本次检查的 qualification agent 中未看到相同依赖的跨任务评分结果命中短路；这不等于产品没有结果存储、任务检查点或其他缓存。保留历史评分展示/恢复与主动发起新评分是不同语义。

## P02 讨论细则（尚未确认）

1. 以每次 provider HTTP 尝试为计费观察单位，关联任务、阶段、尝试/重试、实际服务商/网关/模型/端点和提示/评分规则版本；不只记录最后一次成功响应。
2. 保留服务商提供的输入/输出/推理、缓存读取/未命中/创建数及字段来源；不提供则 unknown，不自行补 0，不混同各协议创建/读取语义。提供商输入总数和缓存字段只有同口径且完整时才校验守恒。
3. 仅保存数值、状态、版本与必要的受控内部关联；不保存密钥、提示原文、邮件或证据正文。指标记录失败不重放成功业务调用。
4. 本地结果缓存命中记录免调用次数和下游采用；服务商前缀命中记录实际报告的缓存 token。前者不是服务商返回的 cache-hit，后者不意味着输入 token 减少。提供商费用和本地避免成本估算分开。
5. 输入缓存命中率 = 同口径缓存读取 token / 输入总 token，只在字段齐全且分母大于 0 时计算；同时展示数据覆盖率，避免只看有 usage 的成功调用。输出、失败/未知费用与重试纳入账本视图。
6. 根据该次 token 与已核验费率计算“缓存折价估算”；未经实际账单/完整费用核验不得称为已核销节省，更不能与本地避免调用估算相加冒充实付降低。预留仍按未命中，保留已有释放规则。
7. 界面复用任务中心/费用详情的可展开摘要；按任务/阶段/模型汇总命中、覆盖、延迟、重试、有效/下游采用，避免新增冗余页面。冷启动、模型/网关切换分别看，不跨隐私域承诺缓存复用。
