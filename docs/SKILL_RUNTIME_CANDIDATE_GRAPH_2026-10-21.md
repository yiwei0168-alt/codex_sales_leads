# G09 正式任务中的候选执行循环

对应 MA24-06，无新增用户确认。新增内部显式入口 `runSkillRuntimeCandidate`；既有配置采集CLI和旧审核器尚未切换到此协议。

## 执行与持久化

- 使用服务器固定的原任务提示、决策记忆和模型配置，不将隐藏任务的空附件元数据重新生成为提示。
- 重用候选主图与持久模型适配器；历史题经正式分发器、普通任务工具日志及恢复规则执行。Skill列表/读取仅覆盖本次候选可见值，不启用账号Skill。其他只读工具精确匹配已验证原回执，不调用原业务处理器；不存在匹配时停止。
- 新工具回执拥有隐藏任务自己的call ID；输出按实际JSON表示规范化，原回执摘要保留在图trace中。旧原任务日志不修改。
- 任务使用普通90秒租约和20秒heartbeat API，保守单调时钟期限与控制检查传递取消信号；私有169租约继续保护候选检查点与模型日志。两者任何一方失效均阻断后续消费。
- 新运行摘要包含协议、原来源摘要、隐藏任务与spec摘要；检查点另绑定模型次数上限，不能复用旧无正式工具日志的图状态。
- 结算在拥有来源复核的账号事务内写入任务结果，再重建来源/冻结/身份；失败回滚结果，不删除独立提交的模型与检查点。再次执行可复用已保存终态，完成结算。

这仍是历史精确回放，`businessToolExecutions=0` 表示未运行原业务处理器；`registeredToolJournalUsed=true` 表示使用正式工具日志适配。新协议为 `skill-instruction-overlay-runtime-v1`，不伪装成旧审核器已验证的协议。
