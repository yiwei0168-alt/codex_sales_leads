# 市场计划缓存写失败后的检查点恢复（阶段100）

市场计划生成属于工作流主结果，`lead_playbook_cache` 只是可选的跨任务复用副本。原实现先写缓存，再返回 `build_playbook` 节点；若缓存不可用，节点抛错，刚生成的计划无法进入图检查点。恢复可能重复计划生成及其费用。现改为缓存写失败只标记 `cacheWriteFailed` 并添加任务告警，仍把计划、知识引用、生成阶段指标和既有额度提交到图检查点。缓存读取失败仍在生成前中止，不因缓存故障盲目发起新的付费模型请求。

隔离 PostgreSQL `langgraph` 检查点以两个独立 Node 进程验证：第一个进程使用三条合成 RAG 引用生成一份合成计划，缓存写入故意失败，并在下一阶段边界暂停；检查点 `next=[discover_candidates]`，计划完整且原有13合成credits保留。第二个进程从同一检查点恢复，进入发现边界；计划生成0次、缓存写入0次、旧阶段重放0次。该验证在发现边界故意停止，没有访问任何真实搜索/模型适配器；验证线程已删除。定向图测试另核对告警、阶段元数据及恢复后完整合成结果。

验证：全量 Vitest 898项/196文件、TypeScript、生产构建、改动文件 lint、生成工作流文档检查和生产依赖审计0个高危漏洞通过。实际业务输入/有效/下游使用0；合成输入3条知识引用、有效计划1份、恢复后下游发现边界使用1份，生成阶段利用率1/1。合成缓存写失败1次，计划输出丢弃0，模型 token/API credits/现金0；真实供应商延迟、节省和用户采用未知。优化机会是让可选缓存故障不造成已完成计划重算，同时由图检查点保证同任务恢复。真实付费计划与完整业务入库仍归A11验收。
