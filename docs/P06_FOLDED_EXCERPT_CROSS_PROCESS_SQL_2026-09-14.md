# 阶段147：P06 折叠评分跨进程与产品 SQL 验收

本阶段复用现有隔离夹具，不调用外部模型或搜索。第一进程把一家公司置于评分前的 PostgreSQL 图检查点；第二进程使用当前 `LeadQualificationAgent` 和 DeepSeek 实际序列化合同，完成一次内存模拟模型响应。变体有 55 条高熵补充证据/事实和一条冲突事实，共 56 条证据及 56 条事实。只有已支持事实的部分冗长原文折叠，冲突来源原文保持完整；请求仍受 61,440 字节上限约束，`supported-excerpt-fold-v1` 及省略原文条数写入评分遥测。改变一条折叠来源的原始内容会使评估依赖指纹失效。

同一跨进程路径调用实际 `persistLeadWorkflowResult`：产品评估表保留 56 条原始证据及 56 条原始事实，证据快照表有 56 条记录，评分阶段遥测和模型用量各一条。检查点保留评分前输入，完成后内部评估一条、合格及交付均为零；第二隔离账号不可读取评估。SQL 夹具及关联的全局合成公司已清理，未产生预留或真实付费调用。既有共享短语无损压缩的 101 条证据/105 条事实也以相同的跨进程和产品 SQL 路径复验通过。

验证命令为 `node scripts/run-tsx.cjs scripts/verify-shared-phrase-score-checkpoint.ts` 及其 `sql` 模式；折叠变体在同一命令前设置 `P06_SYNTHETIC_FOLD_VARIANT=1`。四个模式均通过；类型检查、该脚本 ESLint 及差异检查通过。此夹具从预置已校正候选开始，模型响应为模拟；不能证明真实模型对折叠说明的遵从、最终合格率、任意大单项的分阶段完成或 A11 真实付费闭环。

效率台账口径：两种变体各有一次评分输入、一次有效模拟评估和一次下游产品评估保存，实际用户采用未知；真实 token、API credits、现金成本、供应商延迟均为零/未观察，脚本各运行约 8–11 秒。临时测试失败来自夹具期望编码和指纹断言，修正后复验通过，未重放任何未知付费请求。优化机会是为继续超界的单家公司设计可检查点化的分阶段评分，并用真实、可计费合同核验模型结构遵从；不得把合成利用率推算成市场发现或成本节省。
