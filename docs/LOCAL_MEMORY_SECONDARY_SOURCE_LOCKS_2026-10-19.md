# 消息纠正与工具回执学习的提交期来源保护

## 当前实现

- 消息纠正在识别到更正指令后、查询旧观察和写入之前，调用迁移 154 的消息来源锁，核对初次读取的任务、首条用户消息 ID 和完整原文。锁保留至该纠正事务结束。
- 工具回执学习在锁定当前 extraction job 后，调用迁移 155 的 `lock_local_memory_receipt_source`。按 admission → active account → completed main-agent run → tool calls 顺序锁定。
- run UPDATE 锁通过 `(user_id,run_id)` 外键阻止新建或移入回执；现有回执 SHARE 锁阻止编辑/删除，分页使用同一事务内受保护的输入。此函数不要求存在用户消息，保留工具学习与后续缺失原文处理的独立边界。
- 锁前账号/任务/指令变化抛出 `source_changed`；锁后的来源编辑等待提交。最终租约墙钟校验、哈希校验和观测质量等级保持不变。

## 迁移要求

当前抽取 Worker 代码要求安装至 **155**；消息纠正使用 154，工具回执阶段使用 155。缺少函数不降级为无锁读取/写入。迁移函数为账号绑定 SECURITY DEFINER，只给应用角色执行权限，不给 PUBLIC 或 collector 执行权限。

全新库 CLI 新增显式 `--fresh-pilot-through=155`，保留 135/153/154 历史选项；当前新库验收及恢复后检查要求两个函数存在。备份逻辑快照新增两个函数标记，源/恢复库对比时保留实际存在状态。

## 已验证范围

75 项定向测试、类型和 lint 通过。实际隔离克隆八例覆盖：锁前指令编辑、账号停用、任务失败被拒绝且没有观察/通知；锁内指令编辑、账号/任务修改、回执编辑、回执插入实际等待，提交后完成。作用域限定的测试触发器和全部合成数据已清理。

另通过迁移 155 全新库初始化、旧镜像合成 HTTP 兼容、非空邮箱备份/跨实例恢复，并明确检查恢复后的 154/155 函数；原消息纠正、工具回执学习、四类租约到期和五类 admission 顺序回归通过。[验收收据](evidence/ma24-g03-secondary-source-locks-2026-10-19.json)。
