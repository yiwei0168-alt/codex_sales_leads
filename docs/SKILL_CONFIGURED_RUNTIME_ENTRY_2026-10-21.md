# G09 配置采集入口与正式候选任务

对应既有 MA24-06，无新增用户确认。历史候选的配置入口改为创建并显式认领独立隐藏任务，使用正式只读工具日志执行，再通过带 `taskId` 的历史材料收集器重建审核材料。前瞻候选暂保留原入口，不能据此宣称完整执行统一。

## 执行与重试

- 原任务的冻结计划、输入、基线、Skill、执行身份和签名先校验，之后才创建候选任务。
- 新模型传输的快照摘要绑定原来源、隐藏任务 ID 和服务器任务规范摘要，不能复用旧回放的签名或检查点。
- 配置传输与费用作用域预检在认领之前完成。任务认领仍由数据库租约控制；受控或部分完成的任务拒绝自动重跑。
- 已完成任务重新审计持久日志和完成元数据，核对摘要后复用结果，不创建模型请求适配器、不重新认领或执行工具。之后仍重查原来源和模型签名并重建收集材料。
- 新链路失败不回退旧历史执行器。历史材料保存隐藏任务引用，进入既有新协议审核。
- G09 题目 ID 上限与既有配置入口保持 200 字符；G16 仍为 120 字符。

## 当前验证

23 项配置入口测试与 41 项候选图/日志审计/来源材料回归通过；全项目类型检查和五文件 ESLint 通过。

两次新建迁移至 169 的一次性数据库运行均退出 0。第二次补验实际编译采集入口产生 `historical-collector-v2` 材料，隐藏任务绑定原任务、冻结与评测，正式工具日志包含完成的 `skill_read` 与 `customer_timeline`，每份模型请求的快照摘要均绑定该任务规范。再次启动相同编译入口时禁止网络请求，仍完成审核材料复用；模型日志、工具日志与唯一材料 ID 不变。Skill 保持禁用，实际模型调用 0，临时资源清理。[验收收据](evidence/ma24-g09-configured-runtime-entry-2026-10-21.json)。

这不是固定 Linux 镜像或完整五类组合验收；原任务签名和传输签名由本地临时登记密钥验证，网络与费用适配器为显式合成替代，不能证明真实提供方或生产运行身份。
