The current minimal Colombia/Distributor route uses `gemini-full` conditionally after Brave, Exa and SearchAPI. The product defaults to `gemini-3.6-flash` on Google's Interactions API with `google_search` and `max_output_tokens=12,000`, subject to its existing model environment override (`src/providers/discovery.ts`). The executor schedules at most five rounds and the default provider wrapper at most two HTTP attempts per executed step, so the read-only preview reports at most ten Gemini HTTP attempts. That is **not** ten billable Google queries. [Google's grounding documentation](https://ai.google.dev/gemini-api/docs/google-search) charges Gemini 3 by each query the model decides to execute, and a single prompt can produce several. The [Interactions GoogleSearch schema](https://ai.google.dev/api/interactions-api) lists `search_types` but no per-request hard query-count parameter in the currently published fields. The absence of a listed field is not proof that no private cap exists; it is insufficient evidence to price the current route conservatively.

The same official grounding documentation says Gemini 2.5 and older are billed per grounded prompt, while the [Interactions API model list](https://ai.google.dev/gemini-api/docs/interactions-overview) includes `gemini-2.5-flash`. The [official price table](https://ai.google.dev/gemini-api/docs/pricing) lists its standard text input at USD0.30/million tokens, output including thinking at USD2.50/million, and Google Search grounding beyond the free allowance at USD35/1,000 grounded prompts. Free allowance is **not** assumed for conservative admission. This makes a 2.5 route a possible way to bound the *grounding unit count* by the already bounded HTTP attempts, but does not by itself establish a complete maximum charge for the actual Interactions request, the model's response quality, or acceptance of every current parameter. No model, route, tariff or output limit has been changed. A model switch would require the A11 route confirmation and full request-contract verification; it is not covered by S01, which concerns the market-plan Sol endpoint.
