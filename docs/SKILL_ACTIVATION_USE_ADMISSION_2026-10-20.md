## 行为

自动启用绑定的 Skill 在读取、模型/UI 列表、运行中上下文和依赖方法校验时，先确认当前事务为 read committed，再按信任登记、运行包顺序尝试取得共享 advisory 事务锁。成功的锁保留到调用方事务结束；已有运维独占锁时立即拒绝本次使用，不等待，以避免与调用方可能已经持有的业务来源锁形成反向等待。

隔离级别为 repeatable read、serializable 或无法读取时拒绝，防止锁取得后仍从旧事务快照读取已撤回的资格。取得锁后的资格查询是独立 SQL 语句。已有业务来源、评测日志、运行指纹和最终资格复查继续执行。人工 Skill 无自动启用绑定的既有流程保持不变。
