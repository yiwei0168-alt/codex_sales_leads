# G09 候选进程强制终止与恢复

对应 MA24-06，无新增用户确认。本阶段新增独立工程验收夹具，不改变生产准入或启用规则。

## 实际执行链

在一次性新169数据库和独立受限采集器登录下，以直接 Node/tsx 子进程执行真实候选图、持久模型日志、检查点和时限租约。子进程只继承测试数据库连接与必要系统环境，入口不调用环境文件加载器；网络请求明确拒绝，模型响应合成。

1. 两个请求完成并提交回执，图保存待执行 `skill_read` 检查点后向父进程报告实际 PID。
2. 父进程先回读检查点与两份回执，再向该进程发出 SIGKILL，并等待进程退出。没有通过抛异常来模拟退出，也没有终止中间启动器。
3. 验证租约仍为旧令牌的 running 状态，默认窗口约90秒。提前启动的新进程被拒绝，原回执不变。
4. 不更新数据库令牌、状态或到期时间，等待数据库时钟确认租约自然到期。
5. 另一新进程接管相同评测/arm，恢复待执行图状态，仅发生第2号合成请求；旧两份回执ID与摘要保持不变。
6. 第三个新进程读取完成态，不产生请求或新增回执，返回结果一致。

验收通过 `MA24_CANDIDATE_PROCESS_CRASH=1` 显式启用，避免普通传输日志检查默认重复等待90秒。关闭时明确返回 `candidateProcessCrashRecoveryVerified=false`。

## 验证记录

首跑在子进程快照摘要核对时失败，尚未进入崩溃场景。原因是夹具把带日期及可省略字段的内存对象直接计算摘要，再以JSON传输，跨进程表示不同。修复仅对合成传输快照先做JSON规范化，再计算同一份字节表示的摘要；未放宽产品来源、模型或检查点守卫。

类型检查和三文件ESLint通过。规范化后的一次性新169数据库整轮检查退出0：实际进程终止、默认90秒租约自然到期、提前接管拒绝、旧回执不变、新进程从待执行检查点恢复及第三进程终态零请求复用均通过。既有所有权、事务内租约/检查点、权限、签名回退和编译候选回归也通过。临时进程、文件及数据库容器均已清理；原有三个开发服务保留。[收据](evidence/ma24-g09-candidate-process-crash-2026-10-21.json)。
