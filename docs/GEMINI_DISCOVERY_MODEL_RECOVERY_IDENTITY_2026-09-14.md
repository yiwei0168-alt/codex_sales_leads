# Stage 198 — Gemini discovery model identity in paid recovery and A11 preview

The discovery provider already trims `GEMINI_DISCOVERY_MODEL` and falls back to `GEMINI_SEARCH_MODEL`, then to `gemini-3.6-flash`. The persisted discovery-session dependency previously used nullish coalescing without trimming. With a whitespace-only primary override, the paid request used the fallback model while the recovery digest stayed tied to whitespace; a fallback model change could then leave the digest unchanged and allow old purchased results to be reused under the wrong actual request contract.

One shared `configuredGeminiDiscoveryModel()` now selects the actual request model for the provider, recovery dependency digest and read-only minimal acceptance preview. A blank primary override plus a changed fallback model invalidates the previous checkpoint; recovery stops for review rather than automatically replaying paid work. The preview explicitly shows the configured Gemini model alongside the existing HTTP and unknown server-side query ceilings. This changes no configured value, provider route, search scope, pricing rule or eligibility standard. Checkpoint digest changes for the affected whitespace-only configuration are intentional and fail closed.
