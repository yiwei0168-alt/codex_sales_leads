# 普通记忆抽取的提交期来源保护

后续 Worker 代码已要求安装至 **155**：当前纠正指令复用本页的 154 锁，工具回执阶段使用 155 的任务/回执锁。下文 154 是普通抽取这一阶段的历史要求；[最新来源范围与验收](LOCAL_MEMORY_SECONDARY_SOURCE_LOCKS_2026-10-19.md)。

G03 普通偏好、业务事实及经历抽取在本地模型返回之后，进入短存储事务。先锁定当前 job/lease，随后调用迁移 154 的 `lock_local_memory_extraction_source`：

1. 取得与记忆/知识写入相同的全局及账号 admission 锁，再锁活跃账号。
2. 锁原会话、已完成主任务及会话消息，复核任务的会话归属和首条用户消息的 ID、原文。
3. 会话 UPDATE 锁阻止经外键插入/移入新消息；消息 SHARE 锁阻止编辑其他消息使其成为更早来源。
4. 保留既有写入前后复核、租约墙钟检查及最后 ready 更新，来源锁随同一存储事务提交/回滚释放。

没有在模型调用期间持锁。job-before-source 的顺序与已有纠正 Worker 一致；来源内部采用 admission → account → conversation → run → message 顺序，避免先拿来源行再等待记忆 admission。

后续兼容补强已将观察、纠正、撤销及旧版记忆写入统一为 admission 在记忆键/目标/行锁之前，避免与这里的来源锁形成反向顺序；实际五例并发验证通过。[锁顺序与剩余负载边界](MEMORY_WRITE_ADMISSION_ORDER_2026-10-19.md)。

## 迁移及部署边界

新代码必须先安装 `154_local_memory_extraction_source_locks.sql`。缺少函数会令存储失败并按已有机制排队，不会降级为无锁写入。函数为账号绑定 SECURITY DEFINER，未给应用增加表级更新权限；PUBLIC 和 collector 无执行权限。

全新库命令新增显式 `--fresh-pilot-through=154`，当前 Web 隔离验收使用 154 并核对函数存在。135/153 的历史边界仍保留。此次仅安装至已有隔离克隆及全新临时集群，没有迁移现有业务库、启动正式 Worker 或部署。固定镜像 `25f5acd3` 不含本轮抽取代码。

## 验收及剩余事项

### 纠正与回执学习的租约补强

后续纠正事务和工具回执学习的初始检查也改用数据库墙钟；最终 ready/续租必须仍为同一账号、任务、token、processing 状态且未超过五分钟。零行更新抛出 `extraction_lease_expired`，使该事务回滚；编排层沿用原 token 条件进入重试，不续活过期租约。

实际克隆分别为两函数使用已过 299 秒的租约，再在观察插入后延迟 2.2 秒，验证自然越过到期边界后的观察/通知/outbox 全部回滚，job 保留原状态、token 和时间；相同延迟的新鲜租约对照正常提交。73 项定向测试及既有纠正/回执回归通过。[证据和边界](evidence/ma24-g03-correction-receipt-lease-2026-10-19.json)。这不把三个独立事务合并，也不声称纠正/回执的所有来源行已获得普通抽取同等保护。

33 项定向测试、类型检查及 lint 通过。实际隔离克隆七类并发验证覆盖模型期间消息/账号/任务变化的拒绝与恢复重试，以及存储期间编辑消息、停用账号、修改任务、插入更早消息的实际等待。后四例释放插入测试栅栏后，抽取先提交，编辑再完成；已 ready 的任务复用且不重复生成观察/通知。既有显式/自然纠正及撤销回归通过。全新迁移 154 初始化、Web 合成 HTTP、备份及跨实例恢复退出 0。[收据](evidence/ma24-g03-source-locks-2026-10-19.json)。

只保护普通抽取的存储事务，不将此前工具回执学习/纠正事务改为整个任务原子操作。提交后的编辑合法，此改动不声称自动撤销已提交观察；读取时来源复核及纠正流程继续负责后续变化。真实模型质量、负载/长事务容量、完整当前源码签名组合、当前镜像加载及生产验收仍待办。
