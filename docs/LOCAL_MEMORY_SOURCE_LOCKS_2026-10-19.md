# 普通记忆抽取的提交期来源保护

G03 普通偏好、业务事实及经历抽取在本地模型返回之后，进入短存储事务。先锁定当前 job/lease，随后调用迁移 154 的 `lock_local_memory_extraction_source`：

1. 取得与记忆/知识写入相同的全局及账号 admission 锁，再锁活跃账号。
2. 锁原会话、已完成主任务及会话消息，复核任务的会话归属和首条用户消息的 ID、原文。
3. 会话 UPDATE 锁阻止经外键插入/移入新消息；消息 SHARE 锁阻止编辑其他消息使其成为更早来源。
4. 保留既有写入前后复核、租约墙钟检查及最后 ready 更新，来源锁随同一存储事务提交/回滚释放。

没有在模型调用期间持锁。job-before-source 的顺序与已有纠正 Worker 一致；来源内部采用 admission → account → conversation → run → message 顺序，避免先拿来源行再等待记忆 admission。

## 迁移及部署边界

新代码必须先安装 `154_local_memory_extraction_source_locks.sql`。缺少函数会令存储失败并按已有机制排队，不会降级为无锁写入。函数为账号绑定 SECURITY DEFINER，未给应用增加表级更新权限；PUBLIC 和 collector 无执行权限。

全新库命令新增显式 `--fresh-pilot-through=154`，当前 Web 隔离验收使用 154 并核对函数存在。135/153 的历史边界仍保留。此次仅安装至已有隔离克隆及全新临时集群，没有迁移现有业务库、启动正式 Worker 或部署。固定镜像 `25f5acd3` 不含本轮抽取代码。
