# G09 孤立原件副本的显式运维清理

## 工作流与权限

迁移 158 提供操作库中孤立原件副本的受控清理。只有**不存在任何同 ID 的 `knowledge_asset` 记录**才视为孤立；已归档、共享撤回、登记状态或哈希变化均不足以允许清理。资料仍有记录时继续保留副本。

运维连接必须是副本表所有者，并具有现有 RLS bypass 或超级用户权限；迁移没有创建账号或授予该权限。应用、采集器没有删除副本、读取审计或执行清理函数的权限。只允许显式清单删除，UPDATE/TRUNCATE 继续拒绝。

1. 用 `DATABASE_MIGRATION_URL` 指定运维连接，生成新清单文件：
   `node scripts/run-tsx.cjs scripts/prune-orphan-asset-snapshots.ts --plan-out=<new-plan.json> --before=<UTC-ISO> --limit=<1..100>`
2. 核对清单内的副本 ID、资产 ID、SHA-256、字节数及截止时间，按相同文件显式执行：
   `node scripts/run-tsx.cjs scripts/prune-orphan-asset-snapshots.ts --apply=<plan.json> --request-id=<UUID> --reason=<reason>`
3. 输出已提交的请求 ID、清单哈希、删除数量/字节和数据库时间。若结果不确定，以**相同请求 ID、同一清单与原因**重试核对；已有请求返回原收据，不再删除，输入不一致拒绝。

预览不删除数据，不覆盖已有清单；空清单不能执行。每批最多 100 项是实现上限，不是用户确认的保留策略。远程连接要求 `sslmode=verify-full`。没有自动清理、默认保留期限或调度任务；此入口只作用于当前数据库，不修改备份历史。

## 事务保护

清理与资料写入共用 `skill-memory-global` 排他来源锁，等待已有读取/捕获事务结束，然后重新核对清单的每一行。出现缺失副本、哈希/长度不符、资料恢复或创建时间不满足截止条件时，整批拒绝。删除和不含原文字节的不可改写审计处于同一事务；外层回滚同时恢复二者。审计记录请求、完整元数据清单、清单哈希、原因、数量、字节数、数据库时间和连接身份。

删除触发器还要求表所有者、事务内审计请求及精确行绑定，拒绝伪造上下文绕过。数据库所有者主动禁用触发器属于特权管理操作，不在应用权限保证范围内。

## 实际验证

- TypeScript 与定向 ESLint 通过。
- 一次性全新迁移 158 PostgreSQL：迁移重复应用、只读预览、应用/采集器权限、伪造上下文、不可改写/不可 TRUNCATE、陈旧哈希、资料恢复后的整批拒绝均通过。
- 通过 `pg_stat_activity` 观察精确清理后端实际等待来源读取锁；释放后操作完成，外层回滚保留全部副本并回滚审计。
- 实际运维 CLI 预览、执行、相同请求重试、输入不一致拒绝及审计不可修改通过；删除两份合成孤立副本，保留一份仍有关联资产的副本。
- 首次验收连接缺少 `SET ROLE network_copilot_app`，来源读取函数按权限拒绝。修正夹具后通过，权限未放宽；失败日志保留。
- 旧固定 Web `6b7089c9` 在全新 158 库完成原有登录/隔离 HTTP 检查；新运维脚本与迁移在宿主执行，不声称已经进入该镜像。未重验本轮浏览器、恢复或完整五类组合。
- 临时容器、网络、清单目录均清理，无业务数据删除或模型调用。
