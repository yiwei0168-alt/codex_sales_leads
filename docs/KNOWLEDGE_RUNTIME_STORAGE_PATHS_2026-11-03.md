# 独立运行包的资料路径修复（2026-11-03）

## 问题与行为

当前 Web、API 及 Worker 使用独立打包目录；原件下载、邮件附件、上传、抽取产物、视觉审核和检索部分代码仍相对进程工作目录读取 `knowledge/...`。数据库记录存在并不能保证文件在该目录可读。使用合成原件和不同工作目录复现未配置根目录时的 ENOENT；本轮未据此推断用户某次问答必定受此问题影响。

新增服务端 `KNOWLEDGE_STORAGE_ROOT`（资料目录本身）和 `KNOWLEDGE_SCRIPTS_ROOT`（抽取脚本目录），必须为绝对路径；未设置时兼容源码运行的 `./knowledge`、`./scripts`。本机标准启动器从工作区派生同一组路径供组件使用。数据库继续保存 `knowledge/...` 相对键，前端继续使用原有资料 API，无需暴露磁盘路径或修改界面。

原件读取、上传目录、抽取与审核产物、视觉图片、向量无关检索、邮件附件和下载路由统一解析资料路径。保留权限复查、密文/原件哈希及文件身份检查；增加既存祖先目录的真实路径核对，拒绝向资料目录外的目录链接读取或写入，并拒绝路径遍历、绝对键及 Windows alternate stream。配置的资料根目录本身可以是显式目录链接，按其真实路径检查边界。
