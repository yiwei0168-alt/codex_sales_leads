## 问题与实现

此前普通主图直接构造原生 `PostgresSaver`，其检查点写入事务没有任务令牌/租约条件。隔离对照使用同一已安装 saver：观察检查点表锁等待，等待任务租约自然到期后释放，写入仍返回成功；预期拒绝的断言失败，退出 1。对照只复现原生 saver 的检查点写入，不是完整 SDK Worker，也未运行到原生待处理写入案例。

普通 `executeMainAgentRun` 现使用 `AgentRunCheckpointer`，保持 `langgraph` 表与原序列化格式：

- 线程必须严格等于服务器上下文派生的 `main-agent:<userId>:<runId>`。
- 每次检查点、待处理写入和线程删除持有当前任务行共享锁，写入前和提交前按数据库墙钟核对令牌、running、普通主任务及活跃账号。
- 原 saver 的序列化和 SQL 继续使用；连接适配器将其 BEGIN/COMMIT/ROLLBACK 交给外层账号事务，所有写入、任务锁和最终复查共用同一个客户端，失败整体回滚。适配器按当前锁定依赖的事务接口实现。
- 读取线程前后复查当前任务边界。暂停/取消尚未结算时允许保存图状态，这只授权存储，不授予新的业务执行；任务结算后拒绝旧 saver 写入。

20 秒数据库预算限定单次检查点事务；不续租、不改变任务认领、模型/工具回执，也不声称持有覆盖整个 COMMIT 时长及全部执行期间的期限许可。
