# 主角色缓存读取失败时的重复付费门禁（阶段101）

公开角色校正缓存可能已有同证据、同模型请求契约的完整结果。原校正器将缓存读取异常当作普通未命中，接着执行补证和模型校正，无法证明不会重复付费。现对明确的读取异常在付费工作前暂停；真正的空结果仍按正常未命中处理，`BudgetDeniedError` 继续保留原费用门禁语义。缓存写入失败的已完成结果处理和角色判定标准不变。

合成测试让首次缓存读取故障：补证搜索0次、模型执行0次、有效校正0项；同一候选在缓存恢复后第二次读取为空，补证搜索1次、模型执行1次、有效校正1项。该重试只是合成适配器验证，不涉及真实服务商，也未将首次技术失败标为公司不合格或永久排除。工作流已有失败任务沿原图线程确认重试的入口；本阶段没有以生产任务做该组合的端到端验证。

验证：全量 Vitest 899项/196文件、TypeScript、生产构建及改动文件 lint 通过；生成工作流文档已同步。实际业务输入、有效输出、下游使用、模型 token/API credits/现金均0。合成输入为同一公司两次尝试，首次有效/下游0，恢复后有效1、下游校正输出1；缓存读取失败1次，模型重试0次，技术失败没有生成可丢弃输出。供应商延迟、实际节省与用户采用未知。优化机会是把缓存读取故障与真实未命中分开，避免在无法确认已有结果时重新付款；跨进程真实任务恢复与A11完整闭环仍需验收。
