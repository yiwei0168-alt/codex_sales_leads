## 原缺口与工作流

原主任务在独立来源检查结束后另开事务调用 `finishRun`。资料撤销、范围变化、后到指令或写入等待期间的时间到期，可能落在检查与保存之间。

普通 `executeMainAgentRun` 的新结果及完成态 checkpoint 恢复现统一调用 `settleMainAgentRun`：

1. 在账号绑定事务中取得已有资料/记忆来源门禁，核活动账号及会话，锁任务、租约和原始消息。既有来源迁移缺失时拒绝；实测全新库迁移到 158，不在业务请求中自动迁移。
2. 最后到达的暂停/取消保存空回复；新增未处理指令重排队，旧回答不写入。恢复完成态 checkpoint 遇到新指令时重新进入主图边界，避免重复排队同一旧完成态。
3. 保留任务日志、附件元数据及成功读取的邮件/时间线来源锁，复用当前 Skill、记忆、资料范围和私有回执检查。任务角色、范围和默认偏好/政策快照必须匹配。无数据的 unavailable 邮件结果不是已消费的来源；既有历史回放的严格规则不变。
4. 在保存点内写任务结果、状态事件、助手消息和提取任务，随后重新核对来源、政策快照及数据库壁钟下的原租约期限。来源改变时撤销全部试写，仅保存安全 partial 提示；租约失效时整个结算事务回滚。
5. SQL 来源读取错误也先回滚到保存点，清除 PostgreSQL aborted 状态，再尝试安全提示。连接/回滚/提交结果不确定仍向上抛出，不自动重试事务。

来源写入门禁保留到提交；时间检查发生在实际写入等待结束后，不续租，也不声称在物理 COMMIT 的每个瞬间保持期限有效。普通 `finishRun` 的租约谓词改用 `clock_timestamp()`，并返回实际保存状态，避免对外报告控制覆盖前的旧状态。
