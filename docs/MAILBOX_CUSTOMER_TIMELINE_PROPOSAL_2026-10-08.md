# 邮箱与客户沟通时间线提案

日期：2026-10-08。对应 MAILCRM-01～04。状态：需求已记录；以下设计、选型待用户确认，尚未实现或运行验收。

## 建议的工作流

1. 邮箱采用文件夹导航、邮件列表、阅读区；收件箱、已发送、待学习各自清晰可见。管理账号进入不透明抽屉，固定标题与关闭按钮，正文单一区域滚动。沿用前端审查的批量授权无用户数量上限目标。
2. 同步前选择账号、日期范围及收件/已发送/两者；建议提供最近 7/30/90 天和自定义日期，默认值待确认。展示实际同步范围、进度、剩余量和错误；服务内部分页取完选定范围，可恢复，不把一次取满 100 封当作全量完成。已发送读取 IMAP Sent 文件夹，兼容不同文件夹名称；只存在本地客户端的已发送邮件无法直接从服务器获取。同步本身与授权 AI 学习分开。
3. 客户页左侧国家筛选，中间公司列表，右侧公司详情与时间线。公司列表包含名称、国家、用户指定类型、最近沟通、待确认归属；备注可编辑并提示其将影响该公司的 Agent 理解。
4. 邮件域名、签名与正文用于提出公司和国家候选及依据。公共邮箱、集团共享域名、代理商或一封涉及多家公司的邮件进入待确认；不能只凭 .de/.com 等后缀确定国家。用户可纠正、合并或拆分归属。优先复用现有公司记录，避免重复维护两套 CRM。
5. 同公司在有权限的账号/工作区范围内展示一条时间轴，轴内保留独立讨论线程。按邮件 Message-ID、In-Reply-To、References 等可用头部串联；缺失时标记推断。不能把公司所有邮件当成一个 loop，更不能跨账号自动共享。
6. 时间节点展示日期和时区、主题、关键内容、发件人/收件人/抄送、所属讨论和原邮件入口。参与者按节点/线程实际邮件显示，不推造隐藏密送人员。关键节点如询盘、报价、样品、议价、订单和售后属于建议分类；缺少证据不生成确定结论。切换“重要节点/全部往来”，支持用户修订摘要。
7. 产品 Skill 编排获准邮件读取、候选归属、关键节点总结和增量更新。结构化公司/线程/节点持久化到 PostgreSQL，摘要带原邮件证据和版本；纯 Skill 文件不足以承担整个功能。继续使用既有授权模型边界，不引入默认外发云端。
8. 公司备注作为该公司范围的用户指令上下文，保留编辑版本；邮件原文是不可信资料。两者均不能覆盖权限、发信确认或正式事实核验规则。
9. 建议“删除公司”先移出本产品客户列表并可恢复，保留原始邮箱邮件；不得默认调用服务器删除。此语义仍待确认。

## F13：删除对话历史确认窗口

使用产品深色确认窗口，显示具体对话名称、删除范围和是否可恢复；范围与现有删除 API 的实际行为核对后确定文案，不能承诺不存在的撤销能力。提供“取消”和明确的“删除对话”，默认焦点放取消；支持 Escape、焦点回归、键盘操作。执行中禁止重复提交，失败保留窗口和可读错误。删除对话与停止任务、删除原邮件及删除审计记录的关系必须明确，不通过前端文案暗改后端语义。

推荐：复用当前邮箱、公司关联和权限底座，参考 EspoCRM 的业务流程、Twenty 的 CRM 界面、Reloop 的历史摘要设计。优先自行实现产品 Skill 与持久化时间线，无需整套迁移 CRM 或采购 EmailEngine。
