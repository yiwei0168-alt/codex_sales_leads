## 实际发现

旧固定镜像 `66924a48` 挂载全新命名卷到 `/runtime` 后，非 root Node 创建探针目录返回 `EACCES`、进程退出 1。该专用临时卷已删除。此前通过的是显式指定 uid/gid 的 tmpfs，不能证明默认命名卷权限正确。

## 当前实现

Docker 构建预建 `/runtime`，归属 node（uid 1000），模式 0700；server 启动用随机独占文件实际核对写入并删除探针，失败时在 API 注册前明确拒绝。包目录和 Node 继续只读，状态目录在包外。

新增一次性验收选项 `--main-runtime-durability`（配合 `--main-runtime-image` 与 `--current-schema`），准备检查：

- 全新专用命名卷的权限、正常停机退出与非空状态文件。
- 创建真实 API 持久 thread，更换容器后读回相同 thread 与 metadata，原任务行不变。
- 本地转发代理把请求交给真实 API，观察任务已提交后丢弃 HTTP 响应；真实 worker 的异常路径不能覆盖完成结果或重复助手消息/事件/提取任务，下一 worker 不能重放请求。

类型与定向 lint 通过；修复后的固定镜像及以上运行场景尚待验。全部使用合成数据，目标业务卷未修改；首次模型调用、API 崩溃、备份恢复和目标主机持续运行仍是独立门槛。无新增用户确认、模型调用或外部动作；G14–G20 与内网上线暂缓。
