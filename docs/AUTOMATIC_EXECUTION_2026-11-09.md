# 自动执行替代手动模式

用户确认新路由直接替代用户手动选择模型和路径。本阶段取代 HYBRID-08 的“保留三个按钮并解释”方案；该候选未部署。新对话只保留统一输入框、资料附件和发送按钮，显示“自动执行 · 按任务选择模型与处理方式”。

## 新任务流程

1. 对话、知识问答和新定时任务由服务端冻结 `hybrid-auto-v1` 配置，不使用客户端 mode 决定模型或能力。
2. 已审核的精确固定读取可直接启动；其他符合上下文条件的任务使用 Jev v4 建议。已有历史、附件、知识范围或政策等不符合条件时，继续动态规划，不把这些任务伪装成简单新问题。
3. 主模型请求根据服务端建议和已有工具结果选择冻结的模型链。固定流程用 quick 链（首选 `openai/gpt-6-luna`），程序片段用 standard 链（首选 `anthropic/claude-sonnet-5.5`），动态规划用 deep 链（首选 `openai/gpt-6.1-sol`）。现有两级备选、流式边界、限时、预算与未知结果不重试规则继续生效。
4. 部分结果、异常或程序 handoff 交给强模型动态规划；新增用户要求使旧建议失效。可以继续使用程序工具，但不把模型档位或建议路径当作实际已执行程序的证明。
5. 用户只需提出业务目标。模型不能要求用户切换快速/标准/深入模式。涉及必要缺项和既有高影响动作批准时，继续使用原有澄清/审批机制。

## 权限与兼容

模型档位与工具范围已拆开。业务入口使用完整注册能力，仍逐次执行账户/角色、授权、资料范围、预算和审批检查；interpreter 仍只能调用白名单工具。知识问答入口保持只读和选定资料范围，即使使用强模型也不扩大权限。

旧页面发送合法 mode 时，新任务仍保存自动配置，原输入值只保留用于历史和幂等；非法 mode、模型、角色或执行路径注入继续拒绝。已创建的历史任务没有 automatic 标记，继续使用原模型与能力配置，避免恢复时改写原约定。独立评估、已审核邮件专用执行器不借此改写。

## 验证与限制

153 项自动检查、TypeScript 和 ESLint 通过。包括生产 durableModel 的实际请求配置（提供方为模拟）、成功回执复用、图流程固定读取及 handoff、知识入口只读、旧任务兼容、旧客户端自动配置。真实对话组件的隔离桌面/手机布局已检查。

这次没有新增真实提供方调用，没有用真实业务数据生成验收答案。Jev 沿用已校准 v4，自动选模是新集成行为，真实业务质量、实际路径覆盖、总耗时和费用效果仍需自然任务验证。新的模型链映射是明确记录的实现选择，不宣称已经达到最优。

本机构建与激活证据在完成后追加。旧包和配置保留，支持回退。
