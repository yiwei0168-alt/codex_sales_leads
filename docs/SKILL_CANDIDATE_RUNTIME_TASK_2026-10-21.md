## 服务器绑定

`skill-candidate-task-v1` 与 G16 的 `ma24-evaluation-run-v1` 分开。只接受原任务、冻结、题目、评测与候选版本的标识，服务器重建完整历史任务来源、候选快照、基线投影和运行身份，再核对冻结计划的历史题目、输入、来源、版本及身份摘要。账号和原任务行保持共享锁，冻结锁与入队/认领处于同一账号事务，返回前再次检查冻结期限。

任务使用既有 `main-agent-evaluation` 隔离：会话隐藏、不新增用户消息、不触发普通记忆抽取；普通 Worker 排除该种类，G16 认领函数仅接受自己的 schema。G09 显式认领绑定完整 spec/input/model，生成普通任务租约令牌；重复有效租约、控制中任务及不匹配上下文拒绝。相同绑定入队复用同一请求键。

任务元数据仍要求非空知识范围，但原任务未指定知识范围时，执行上下文保持原来的未限定值，不把业务只读工具错误限制到知识库目录；原任务指定知识范围时保持该限制。模型与完整附件提示必须继续使用已固定的服务器原任务快照，不能将隐藏任务的空附件元数据当成新的模型输入。

## 正式分发守卫

G09 上下文包含服务器派生 spec 摘要。发现/说明/执行入口先按账号、任务、租约和 schema 读取存储的冻结计划，再重建来源和身份；摘要不是授权替身。`executeRegisteredTool` 对直接调用同样重核，且只允许 read。G16 保留原知识范围和只读限制，普通任务拒绝评测上下文。
