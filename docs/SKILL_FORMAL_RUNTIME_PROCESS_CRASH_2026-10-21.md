# G09 正式任务的提交后进程崩溃恢复

对应既有 MA24-06，无新增用户确认。产品代码基线为 `6d700395`；本轮增加独立验收夹具，不改变产品执行器。范围为一个历史候选的编译采集入口及新正式任务协议。

## 实际故障与恢复

1. 仅在验收编译器中注入故障：正式分发器完成 `skill_read` 并提交工具结果后，先输出终止标记，再向当前测试子进程发送 `SIGKILL`。生产构建不包含该注入。
2. 确认子进程退出失败、隐藏任务仍为 running、两份模型结果与一份完成的 Skill 读取回执存在；保存的图仍将该读取列为 pending。
3. 提前启动新进程，确认未能接管，模型/工具行及私有执行令牌不变。
4. 只读轮询任务与私有执行租约的数据库墙钟，等待默认租约自然到期；不改截止时间、状态或令牌。
5. 新进程执行相同任务与评测，恢复 pending 读取并完成。恢复期间对已完成模型步骤 0、1 的 HTTP 请求会直接导致夹具失败；最终旧模型/工具完整行保持不变，私有执行令牌已变化。
6. 继续原有完成任务零请求复用、签名/任务绑定、统一审核两臂证据及材料锁检查。

## 结果

新建迁移至 169 的数据库案例退出 0，以上正反例全部通过。Skill 保持禁用，真实模型调用 0，临时测试容器已清理。[收据](evidence/ma24-g09-formal-runtime-process-crash-2026-10-21.json)。

原有短租约组件和旧候选崩溃开关的结果保留；本案例由 `formalTaskProcessTerminatedAfterCommittedRead`、`formalTaskDefaultLeaseNaturallyExpired` 等新协议字段证明，不改写旧字段。
