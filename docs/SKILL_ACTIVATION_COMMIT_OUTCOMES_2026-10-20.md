# G09 启用事务的两种未知提交结果

对应既有 MA24-06。本阶段不改变启用政策或增加生产资格；新增一次性数据库故障验证，复用当前正式 `changeSkill` / 最终启用适配器、事务组件及162数据库守卫。正向 readiness 仍为明确的测试替身，不创建 human 审核。

## 方法

仅在 `MA24_DISPOSABLE_LOCKED_POLICY=1` 且数据库为回环地址上的指定临时库时启动协议代理。代理仅监听127.0.0.1，透传真实PostgreSQL v3认证、查询和结果，不记录SQL、参数、认证或连接串。此组件不实现TLS，只用于本机一次性库；不提供生产代理或固定Linux/TLS验收证据。

故障只针对实际 `skill_activated` 审计 INSERT 已获得 `INSERT 0 1` 的事务，普通连接检查及事务不受影响：

1. **COMMIT已成功、确认丢失**：收到后端 `COMMIT` 成功和空闲状态后不向客户端返回，断开连接。调用方收到失败，真实库必须已保存一套Skill状态、工具回执和审计。之后人工停用测试Skill，再以相同调用重读，只返回已提交回执，不能重新启用或新增审计。
2. **COMMIT未送达**：实际启用/回执/审计均已写入开放事务，代理在COMMIT送达前关闭上游。真实库必须整体回滚，工具调用仍started且无输出/审计。关闭故障后，由测试显式重试原调用，才能提交单份结果；再次重读不得新增审计。

两种故障均要求客户端观察到失败；真实后端提交/丢确认/阻断计数必须准确，协议解析错误为0。正式事务层不自动重放回调；本夹具的显式重试不代表Agent已完成租约恢复或生产工作流自动重试。
