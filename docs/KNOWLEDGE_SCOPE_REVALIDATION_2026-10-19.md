# G02/G09 资料范围的来源复核

## 修复的缺口

此前片段来源复核检查账号权限、活动版本、正文、原件哈希和坐标，但旧索引/v3 的片段 SQL 及原件回执复核没有持续限制当前资料库范围。资料在读取后由产品库移到公司库，正文、ID、SHA-256、可见性都不变时，选定产品范围的任务仍可能接受旧来源。

现在 `currentKnowledgeChunkEvidence` / `authorizedKnowledgeChunkIds` 可接收已有资料库范围，两种索引均按当前文档的集合 slug 过滤。检索工具在返回前、RAG 回答在发送模型前和生成后均传递实际范围；比较工具始终限制产品库。

主 Agent、恢复与 Skill 回放共用的 `assertCurrentKnowledgeMessages` 同时保留每次调用的范围：

- 搜索沿用实际执行的优先级：任务 `knowledgeScope` 优先，否则使用该次搜索的 `collections`。同一片段在两个不同范围调用中出现，必须分别通过，不能合并范围后放宽。
- 比较证据保持产品范围；显式任务范围不含产品时拒绝。原件回执按任务范围重新查当前资料归属。
- 无范围的普通片段复核仍保留原有账号权限语义；向量树读取沿用其已有范围检查。
- 来源变化的用户提示补充“范围”，旧来源生成的回答和后续动作沿用原有停止规则。

这沿用既有资料范围及权限边界，没有新增确认或扩大可读取范围。

## 验证

- 8 个文件共 79 项定向测试通过，包含同片段不同范围、任务范围优先、固定产品比较、原件范围以及 RAG 生成后扣留；类型与定向 ESLint 通过。
- 一次性全新迁移 158 PostgreSQL，四组 `legacy/v3 × private/shared` 实际来源分别通过：原文/哈希/ACL 不变，仅移动所属集合；调用实际主图实现，在合成模型回调中提交移动，生成后不返回原回答、清空待执行动作；恢复挂起动作时也拒绝，动作适配器调用为零；恢复集合后正向完成。
- 同时核对另一账号对私有/共享片段的访问、原件工具实际元数据输出，以及移出范围后原件回执拒绝。没有读取磁盘原件字节，本项是范围保护，不替代原件完整性验收。
- G09 的账号绑定事务保留来源门禁；`pg_stat_activity` 观察到精确写入后端等待 advisory lock，锁内仍见原范围；释放及写入提交后，范围查询拒绝旧来源。
- 模型与动作均为合成适配器，外部模型调用和消息发送为零。没有验证正式 worker 的持久最终保存、未知提交恢复、真实模型质量或完整 G09 启用。
- 该轮宿主源码验证完成后仅补充了两处中文提示中的“范围”，随后 79 项定向回归通过。旧固定 Web `6b7089c9` 只用于新库的既有登录/隔离兼容检查，本次源码修复尚未进入该镜像，不把宿主主图测试称为编译 HTTP 验收。
