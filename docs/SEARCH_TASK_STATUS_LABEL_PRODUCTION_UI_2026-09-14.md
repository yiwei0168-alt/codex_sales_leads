# 搜索任务完成标签的本地生产验收

阶段120。对话任务卡原先仅按 `assistant_action.status=completed` 显示“已完成”，即使最终保存数低于目标；任务详情则显示“运行结束，目标未填满”。现由 `searchTaskStatusLabel` 共用状态口径：完成且已保存数达到目标为“目标已满足”，低于目标为“运行结束，目标未填满”，历史结果缺最终数量为“运行结束，最终数量未记录”。失败等非完成状态继续显示原状态。数值0保持已知0，不从候选池或其他任务倒推。

本地生产构建在独立端口3018运行。`scripts/verify-authenticated-ui.ts` 使用隔离账号和实际 PostgreSQL/API，增加三条合成对话卡及任务详情的达标/短缺/未知断言。Chrome 1366×900 和390×844 各33组、合计66组页面检查通过；API真实读取，浏览器禁止外网及未列明写入。临时账号、公司和检查点清理；没有搜索、模型、SMTP或真实费用。

首次把验收基址指定为 `127.0.0.1:3018` 时，脚本停在登录页；诊断性复测没有捕获到登录 POST。随后只读端口核查发现该地址已有较早启动的独立 Node 监听进程，而本轮新生产服务监听 `0.0.0.0`/`[::]` 的同端口；`localhost` 解析到 `::1` 后到达本轮服务，两次完整通过。未操作较早进程。脚本增加登录响应和会话检查，以免把登录失败误报为后续页面缺失；这不代表真实 HTTPS 部署验收。

验证：968项测试/203文件、`npm.cmd run typecheck`、定向 ESLint、`npm.cmd run build` 及本地生产 Chrome 66组通过。真实自然语言到搜索、模型判断、供应商账单和最终合格数量仍属 A11 未验收项；本轮不改停止规则、候选质量或冻结哥伦比亚测评。
