# Proxy traffic isolation: short readiness passed, long streams failed

Separate cached proxy pools now serve OpenRouter decisions, generation and metadata. Retiring a failed decision pool cannot retire the generation pool; injected transports, model selection, proxy requirements and no-retry accounting remain unchanged. Thirty transport, stream, cancellation and receipt tests passed, with typecheck and lint. This prevents cross-lane pool retirement by construction; it does not prove that shared sessions caused prior provider failures.

The frozen three-request same-process readiness test passed 3/3 with full READY responses, usage and generation receipts: 4711, 5240 and 2370 ms. No artificial failure was induced in those paid calls. Sources were frozen before execution; these results do not establish long-stream reliability or business quality acceptance.

Two subsequent independent longer synthetic probes used about 3,200 requested words, the existing primary deep model/profile, bounded existing timeouts and no retries. Default protocol received HTTP 200 headers at 8773 ms, then failed with TypeError at 54179 ms. An explicit diagnostic-only HTTP/1.1 proxy dispatcher received HTTP 200 headers at 1462 ms, then failed at 37385 ms. Both outputs and charges remain unknown; two additional unknown charges are retained, never zero. Default product protocol was not switched. The comparison does not isolate HTTP/2 as the root cause, nor support one fixed 27-second cutoff. Error chains for these post-header failures were not retained beyond TypeError, so they cannot be classified more precisely from these probe files.

A no-auth/no-model drip endpoint probe through the proxy returned HTTP 400 before a stream, making it inconclusive; it is not long-connection evidence. Local TrojanX configuration was not altered or restarted. Further full paid evaluation is not justified until a stable long-stream path is established. Next diagnosis needs proxy-side logs or a different working proxy exit under the existing routing rules, and a controlled long response check. Production services were not restarted; the application isolation change is committed but not activated in the already running service.
