# 混合路由与业务效率评测集 v1

状态：**设计完成，尚未执行模型评测**。基于 `hybrid-auto-v1` / Jev v4。数据为合成业务数据，不含生产邮件、客户内容或凭据。用户明确要求比较产品任务时间和成本，因此本目录记录产品评测协议，不恢复开发效率台账。

## 一、路由准确性：96 条

| 类别 | 数量 | 例子 | 首选结果 |
|---|---:|---|---|
| 单客户进展、单项资料原文 | 24 | 查客户近期往来、查型号供电规格 | 固定流程 |
| 已知多步骤处理 | 24 | 多客户排序、分页汇总、分渠道搜索、补证评分 | 程序片段 |
| 判断、歧义、草稿或混合写入 | 24 | 判断谈判意图、先查后添加客户、起草回复 | 动态规划 |
| 上下文保护 | 24 | 历史对话、附件、已保存政策、指定知识范围 | 跳过初始 Jev，动态规划 |

共 12 个样本家族，每家族 8 条。按家族分成开发集 32 条、保留验证集 64 条，同一家族不跨集合。包括中英文、公司名/域名、否定限定、组合动作、路由指令注入、模糊对象。一个完全相同的问题故意配不同政策上下文，用于检查保护条件。

数据文件：`routing-cases.json` 含建议标签、理由和入口预期；`routing-inputs.json` 仅含模型可见输入。**不得向 Jev 提供 expected、family、stratum、rationale 等评分信息。**

### 分开测什么

- 入口契约：8 条规则直达、24 条上下文保护、64 条需要 Jev。前两组不能算成 Jev 正确回答，也不能假装产生了路由模型费用。
- Jev 判断：记录原始四项概率、解析状态、冻结阈值后的建议。只在真正调用 Jev 的样本上报告准确率、混淆矩阵、各类 precision/recall、macro-F1、可用率和路由延迟。
- 完整初始分配：在所有样本上报告最终首选路径命中率，单列规则/保护贡献。开发与保留集独立报告，不合并成一个好看的数字。
- 实际执行：仅靠路由建议不证明执行了程序。第二套业务评测通过工具轨迹验证固定流程调用、真实 WASM 片段、普通工具规划、handoff 和最终模型链。

标签表示“当前契约下首选路径”，不是唯一安全路径。固定/程序任务退回动态规划属于保守漏分；把混合写入任务错误建议为程序片段属于动作边界误分。**误分和实际越权执行分别统计**；程序宿主仍须拒绝未授权动作。

建议验收线（本阶段设计建议，不是用户逐项确认、也不是已通过结果）：保留集 macro-F1 ≥0.90；固定/程序各自 precision ≥0.95、recall ≥0.85；动作边界误分 0；上下文保护额外 Jev 调用 0；Jev 可用率 ≥95%、成功调用 P95 ≤2.5 秒。失败/超时不能从分母删除，另报全请求耗时和未知调用比例。

这些标签由实现方按契约拟定，**不是独立盲测 Gold**；作者已了解旧评测，家族隔离仅针对本套。运行前对语义标签作独立复核并冻结修订；有争议的标签先裁定，不根据模型输出倒改答案。只用开发集调阈值；看过保留集结果后调整方案，旧保留集只能做回归，另取新样本验证。不能把 0/n 风险误分解释为真实风险为零。

## 二、业务时间与成本：24 个任务

使用 12 家合成公司、48 封合成邮件、4 个型号的当前/历史规格以及两份带数量条件的报价。固定时间与数据版本；任务 ID、提示、来源、缺项和检查项在 `performance-tasks.json`，模型输入在 `performance-inputs.json`，原始数据在 `business-fixtures.json`。

| 工作负载 | ID | 核对重点 |
|---|---|---|
| 单客户/单资料 | P01–P06 | 最新往来、日期、正确版本、原文引用 |
| 批量读取与汇总 | P07–P12 | 排序、分页末页、时区、40 封范围计数、缺项 |
| 搜索与研究链 | P13–P15 | 渠道/国家覆盖、域名去重、补证/评分/复核回执 |
| 分页故障 | P16 | 已读范围与部分结果披露，不假装完成 |
| 判断与边界 | P17–P24 | 同名澄清、责任人推定、报价条件、推荐依据、未发送草稿、拒绝跨账号、未知期限、新旧版本原因不明 |

任务分组仅描述负载，不是强制路由标签。澄清、拒绝和如实部分结果仅在该题事先规定的终态下算正确；普通任务失败或意外拒绝不能算成功。

### 三组配对对照

| 组 | 编排 | 主模型 | 用途 |
|---|---|---|---|
| A | 纯动态规划，无 Jev/固定入口/程序封装 | 全程冻结 deep 模型链 | 同能力动态基线 |
| B | Jev＋固定流程＋程序片段＋动态回退 | 与 A 完全相同的 deep 链 | B/A 分离编排收益 |
| C | 当前生产自动方案 | 固定 quick、程序 standard、动态 deep | C/A 总效果，C/B 自动选模增量 |

A 是能力对齐的动态对照，**不代表历史所有用户手动模式的平均表现**。三组使用相同账户角色、注册叶工具、资料和业务政策、预算边界、问题与答复要求。A 只移除封装入口及对应提示，保留完整叶工具发现契约；B/C 保留生产完整程序 schema，不能重犯旧探针删掉契约导致程序不用的问题。C 的模型与备选顺序直接冻结实际配置，不能只比较最便宜一次。

每题每组 3 次，共 **216 次任务**，72 个三组配对区块。`paired-schedule.json` 冻结随机顺序（seed 20261109），ABC 等六种组内顺序各 12 次。先执行预定 6 题首轮、三组共 **18 次冒烟**，六种顺序各一次；它们属于 216 次，不重复计费。如果协议、夹具和回执身份未变，可直接复用，剩余 198 次。冒烟用于检查执行链、质量和记账，不据此宣布提速。

### 真实执行与数据回放的边界

本地公司、邮件、资料工具需使用隔离租户数据库中的真实实现，程序必须执行真实 WASM，模型调用必须真实请求并保存回执，不能用 sleep 或预制答案代替。符号 ID 在准备阶段绑定真实合法 UUID，所有组恢复同一快照，各重复用新任务与幂等键。账号归属、来源坐标和分页必须保持真实工具结构。

P13–P15 的可重复主实验使用合成的公开网页/搜索证据夹具（`.invalid` 域名；并非抓取过的真实网页），评分/复核等叶模型仍真实执行。适配器须将这些字段呈现为完整来源工具记录。这能比较同样数据上的编排和模型处理，但**不代表真实外部网络成本和时延**；回放费用不能冒充真实搜索费。准备数据的共享费用另列，不重复归给每个任务。

因此另设 `live-external-tasks.json` 的 L01–L03：真实英国分渠道搜索、英德搜索、两家公司实际补证评分。每题三组各三次，额外 **27 次**，与 216 次分开报告。L03 的两家公开候选须在任何对照运行前独立选定并绑定同一资料起点；目前该绑定尚未完成。不得用 A 组结果当其他组起点。联网结果变化、缓存和供应商波动保留在日志中；实时结果的角色、地域和引用需要独立核验，不仅看返回家数。完成这一轨道前，不宣称外部搜索全流程已降本提速。

### 时间、成本与质量口径

时间同时记录：用户提交到最终可用答案可见、API 接收入队到答案持久化、排队、Jev、主模型、工具、保存、界面轮询；首次有用输出单列，心跳/“处理中”不算。缺少浏览器埋点时首项为未知，不能拿图执行时间顶替。并发工具的耗时按时间区间计算关键路径，不把并行子调用简单相加。

成本逐次记录 router、主模型、补证/评分/复核模型、搜索/抓取接口、备选/失败/恢复请求；保留 provider generation/request ID、输入/输出/缓存/reasoning tokens、真实费用与币种。按唯一计费请求去重：一次请求出现在多个收据中只能计费一次；重复编号但金额矛盾须核对。未知费用为 null，报告已知下界及未决项，不能写成零。搜索 credits 需用当时实际账单/价目映射，未映射不硬转美元。没有可核算账单的本地计算只报资源和时间，不假称无成本。质量评审费用与被评任务费用分列。

先逐题检查硬性条件：无串客户/越权/未经授权外部动作；没有编造日期、价格、规格或覆盖范围；引用归属正确；完成题目指定字段或明确规定的拒绝/澄清/部分终态。数值、排序和范围用机械检查；判断与草稿匿名交给评审，评分：事实 40、完整性 25、引用 20、范围与不确定性 10、可读性 5，≥85 且硬门槛通过。不给评审组别、模型或时间费用。

建议质量门槛：正确终态 ≥95%、严重违规 0，C 相比 A 的质量下降不超过 5 个百分点。质量未过，不宣布性能成功。建议性能目标：C/A 全部提交的实际总费用减少 ≥20%；同题正确配对的中位任务耗时减少 ≥20%，P95 不恶化超过 10%。这些是目标，不是承诺。报告 A/B/C 各自结果及 B/A、C/B、C/A；只在质量合格配对上谈成功任务速度，同时列出全部失败率、超时和未决计费，不删掉失败来美化结果。再报“全部花费/正确终态任务数”的有效成本。

按任务聚类做配对 bootstrap（重采样任务 ID，保留该任务三次重复），报告 95% 区间和逐题结果；三次重复不当作三个独立业务题。缓存命中、模型备选、故障/拒绝题单列，主结果按原分组保留，不事后只挑无故障样本。24 题不足以证明细分场景的稳定收益；区间跨零时结论为尚不确定。

## 执行准备与当前交付

- `design.mjs`：可复现生成两套数据和配对顺序，不发起模型调用。
- `validate.ts`：离线验证 96 条入口契约、分组隔离、输入不含答案、合成数据计数、配对完整性和顺序平衡。**不验证 Jev 语义准确率。**
- `observations.schema.json`：未来执行记录结构，避免遗漏排队、路由或叶模型费用。
- `freeze.mjs` / `manifest.json`：冻结样本、协议、校验器和相关产品源文件；`--check` 检查漂移。设计冻结与正式运行冻结不同：正式运行还需绑定评测租户、工具适配器、源快照、已批准的费用保护、模型/提供方配置和语义标签审核版本。

命令：`node experiments/hybrid-evaluation-v1/design.mjs`；`node scripts/run-tsx.cjs experiments/hybrid-evaluation-v1/validate.ts`；`node experiments/hybrid-evaluation-v1/freeze.mjs --check`。

现有 program-pilot 不能直接承担本套 24 题正式评测。完整执行器、隔离数据导入/工具适配、浏览器时钟与逐项费用归集尚需接入；本次交付不假称已经可直接开始 216 次付费执行。沿用已有费用保护，不自动提高账户预算；未知请求先核对回执，禁止重复调用。首批完成准备后按 18 次冒烟、路由开发/保留验证、其余配对和真实联网补测逐步执行。
