# 德国多源搜索工具 v2.0 全量重测报告

## 结论

- 质量门禁通过后，已把评测范围从旧版筛出的 81 家扩大到全部 207 家唯一公司、253 条工具来源记录。
- 207 家均使用本次新抓取或同日重新验证的证据完成主角色识别和 v2.0 评分；旧证据引用为 0。
- 正式工具榜只比较搜索结果的线索价值。公司只进入一个主角色通道，不因合作路径文本复杂度加分，也不为排行榜重复生成独立路径复核。
- 成本优化成功：有效运行的模型 token 总量为 7,757,415，低于旧 81 家流程的 10,545,272；候选数增加 155.6% 的同时，总 token 下降 26.4%。

全量有效运行记录了 579 次模型请求，其中 113 次失败：54 次为 schema/供应商重试，59 次发生在 DeepSeek 额度耗尽期间。失败项均按候选粒度重试，没有重算已完成公司。

### 事故成本口径

本次开发过程还发生了两类不应计入稳态成本、但必须计入实际实验成本的浪费：

- 错误角色归一化的首轮纠偏：额外 236 Tavily credits；模型 token 未在阶段完成前落盘，按修复后同规模纠偏的 2,953,703 token 估算，误差预计在 ±20%。
- 配置的独立高能力复核端点额度不足：193 次请求返回 403，未返回可计费 token 用量；结果未采用。

事故计入后，本次实验估算为 932 Tavily credits、约 10,711,118 模型 token。单位公司约 4.50 credits、51,745 token；即使计入事故，仍分别比旧 81 家基线低 16.7% 和 60.3%。候选数增加 155.6% 时，事故口径总 token 仅比旧流程高约 1.6%。

未配置部署网关的美元费率表，因此本报告不伪造货币金额；credits 和供应商返回的 token 为实际计量，首轮缺陷 token 明确标记为估算。

## 已实施的成本控制

- 复用 24 小时内不可变证据并重新绑定本次 run ID，不重复搜索 81 家已验证证据。
- finding 引用证据全部保留，未引用上下文限额并压缩长摘录。
- 模型批次同时受公司数和序列化输入预算约束；结构化评分温度固定为 0。
- 失败仅重试缺失候选；39 家额度失败项恢复后定向重试，其他 168 家未重算。
- 模型用量在纠偏和主评分阶段完成时立即写检查点。
- 工具榜复用一次公司级评分映射所有搜索工具，不按工具重复评分。
- 工具榜跳过合作路径独立盲审；产品开发流程仍可按冲突和边界触发高能力复核。

## 下一步优化建议

1. P0：在启动大批次前做供应商余额/最小请求预检，避免额度耗尽产生大量零输出失败请求。
2. P0：把纠偏和评分改为批级增量检查点，记录每批输入、输出、token、重试和丢弃原因。
3. P0：对模型枚举值使用前缀、后缀和别名契约测试；高置信度却无角色时自动阻断，而不是继续评分。
4. P1：工具榜采用“先全量轻评分、只复核 Top-N 边界和确定性冲突”的两阶段路由。
5. P1：对明确长尾公司设置搜索停止条件；补充搜索仍无公司、网络产品或目标客户证据时直接低分/不通过。
6. P1：配置版本化供应商费率表，使 token/credits 可自动换算为实际货币成本。
7. P2：持续记录 RAG chunk、证据条目、评分输出、合作路径和邮件段落被下游实际采用的比例。
